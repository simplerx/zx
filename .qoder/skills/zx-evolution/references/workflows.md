# 子系统工作流

先按 `SKILL.md` 建立基线，再使用本文件。所有命令从仓库根执行。

## 1. 语言与双前端

Zx 前端是默认路径；C 前端保留用于交叉验证，不能只改一边。

1. 在 `src/lex.c`/`src/parse.c` 与 `bootstrap/lex.zx`/`bootstrap/parse.zx` 同步实现。
2. 新 AST 节点只追加到 `src/ast.h` 和 `bootstrap/parse.zx` 的 NK 枚举末尾；同步 kind 名称、dump、装载和所有分派。
3. 优先在 sema 脱糖到既有节点，避免不必要地扩散新语义。
4. 添加词法、语法、位置、错误恢复与 fmt 的正反例。
5. 重建 `zxc`/`zxfe`/`astdump`/`lexdump`，运行三组对拍：
   ```sh
   sh bootstrap/diff_ast.sh
   sh bootstrap/diff_lex.sh
   sh bootstrap/diff_errors.sh
   ```
6. AST 对拍比较包含位置的完整输出；错误路径对拍比较首个诊断码。两边都拒绝的片段跳过，不能把工具跳过的文件误报为覆盖。
7. 新语法必须同步 tree-sitter `grammar.js`、生成物、高亮/查询与 LSP 推断/snippet。
8. 隐式捕获启发式必须由臂位置门控；else 臂按普通表达式解析。修改 `starts_value` / `starts_binop` 等判定时同时覆盖 `i + 1` 与 `f(x)`，并实跑检查后端符号名，不能只依赖 check。

## 2. 类型、泛型、comptime 与反射

- 类型身份看声明节点，不按跨模块名字合并；别名才共享身份。
- 泛型实例化、克隆与静态槽必须区分模板、实例和独立嵌套类型。不要复制实例后重复检查函数体。
- `const` 是编译期值，`let`/`var` 是运行时槽位；编译期解释器与运行时不能产生两个答案。
- 反射入口保持唯一 `@type`。当前结构以 `kind` 分派；新增反射信息先判断属于哪个 kind 载荷，不堆通用占位字段。
- 编译期专属描述符不得逃逸到运行时。添加正例同时添加运行时拒绝例。
- 测试覆盖：不同实例、跨模块、辅助函数实例化、编译期/运行期边界、非法运行时物化、LSP 字段/变体补全。
- 方法接收者转换只放在点调用检查里，不扩大普通赋值/传参 coercion；按大小选 ABI 不再恢复。不可变值/只读指针矩阵必须覆盖 struct/union/enum，并用 `*const Self → *Self` 负例守住 const。

## 3. 内存安全、tag 与借用

- tag 默认关闭，`tag.enable;` 才开启；堆、局部存储、栈分配、栈临时值与捕获借用只建 `TagSlot`，不能再加独立栈账本。关闭时 E0503/E0512/E0532 一并关闭。
- 符号的 `storage_tag` 表示自身存储，`tag_id` 表示当前值来源；取变量地址与读变量值必须走不同身份。捕获值继承载荷来源，`*t` 与对捕获值取地址才建立借用标签。
- 动态 `for` 必须继承实际元素值/字段来源，不能只继承序列背存；来源混合、缺失或长度未知时报 E0521。绑定状态从对应 `TagSlot` 读取，普通 free 也必须得到 `TC_FREED`。非零下界切片按 `[offset, offset + len)` 筛选元素与数组群记录，不能用切片长度直接比较原数组下标。数组字面量要为每个元素建立索引字段账。
- 审计借用出口时同时覆盖整数 cast、分支/switch 合流、格式字符串、可选/错误聚合解包、数组字面量和反射 `Field.ptr`；作用域清理只释放本层水位之后的新槽，不能按离开作用域的符号反向释放外层存储。
- 编译期推测检查（`g_ct_checking`）只验证克隆体，不创建运行期标签槽；真实 CT 执行也不能建槽。诊断后的 AST 可能缺 `ty`/`sym`，标签传播与收尾检查必须继续安全返回。分支未确认释放报 E0528 后按“未释放”恢复，不能级联 E0515。
- 覆盖所有逃逸出口：实参、返回值、字段、全局与数组元素；分支释放需要显式确认。
- 检查 pass 顺序、缓存和合并状态；未分析、确认安全、确认危险必须可区分。
- 修改账本时同时验证默认关闭与显式开启路径，避免只在开启状态测试。
- 负例必须稳定得到目标错误码，不能因编译器崩溃或无关首错而假绿。

## 4. 后端、ABI 与平台

- 类型布局只由 `src/ty.c` 决定；后端不按大小猜测接收者 ABI。
- 检查局部/全局/extern/静态初始化是否使用同一 C 表示；数组、切片、optional 与字符串各有特殊形状。
- 助手去重按稳定 C 类型名，不按 `Type*` 指针。
- 对 codegen 修复保存 `--emit-c` 断言，并编译实跑；仅 sema 通过不足以证明 codegen 正确。
- 校验 dev 与 release；优化档不能改变正确性。
- 多目标构建必须每目标独立子进程，缓存按目标隔离；不得在同一进程连续切换全局 sema/backend 状态。
- 平台专用 API 放 `src/platform_std/` 镜像；通用 std 不直接写 Windows/POSIX 分支。
- 目标能力不支持某类型时给早期诊断，不静默降级，也不把能力边界误报为 compiler bug。

## 5. 标准库

1. 先确认现有 API 是否已有真身；不要增加与真身混淆的别名。
2. 明确公开边界：容器字段/方法默认私有，跨模块使用必须 `pub`；内部辅助保持私有。
3. 遵守分配契约：堆分配失败返回 optional，由调用方处理；`stackAlloc` 不 optional 化。
4. 热路径先量化，再改分配、拷贝、锁或唤醒策略。不得为 benchmark 牺牲正确性。
5. 覆盖空输入、边界、OOM、所有权、并发（若适用）和实际文件/系统行为。
6. 同步 `std/std.zx`、用户文档、LSP 成员表与双前端验证。

## 6. task 与并发运行时

- 先复现并定量：worker 数、任务数、递归/挂起深度、取消与超时。
- 一个任务一个消费者时可用单唤醒；关闭、广播通知和 worker 退出必须唤醒所有相关等待者。
- 复用纤程/任务前整体重置状态；挂起、递归、等待和取消中的任务不得进入空闲池。
- 句柄复用前摘除旧身份，避免陈旧句柄访问新对象。
- 锁内只做内存操作；磁盘 IO、进程 IO 与 stdout 发布放锁外。
- Windows 与 POSIX 的同步原语、纤程切换和超时语义分别验证。
- 至少运行 task 全组、多轮并发用例与 `tools/stress.sh` 的并发阶段；单次通过不算证明。

## 7. CLI、增量构建与格式化

- 所有子命令从 `argv[0]` 定位兄弟工具，不依赖调用方 cwd。
- 进程启动不拼 shell 命令；参数、重定向句柄与超时由驱动直接管理。
- 增量缓存以内容和目标隔离；重写相同内容不推进 mtime，跨版本缓存不串用。
- fmt 必须保持语义与幂等；对 cast、optional unwrap、数组填充、命名空间点、尾逗号重点验证。
- 覆盖帮助、版本、错误退出码、带空格路径、工程搜索路径与 vendor/deps。
- 工程编译/链接输入以 `zx.json` 为唯一清单源：`deps` 管 Zx 工程，`vendor` 管远端来源，`csrc` 管 C 源码目录/`.clib`，`libs` 管预编译库路径/系统库裸名。
- `include/add/fetch/sync` 才修改清单；`build/run/test/cbuild` 只读取，不联网、不改写。生成绑定不得夹带 `@link`；手写单文件绑定的兼容入口仍保留。
- 依赖工程递归贡献 `deps/vendor/csrc/libs`；C 输入相对声明它的工程根解析。本地工程不复制，远端只按 `zx.lock` 复现，fetch 不得借同步引入未锁定来源。
- 模块 stem 的 C 单元名全局唯一；工程 main、递归 deps 与路径解析必须同步 C 前端、Zx 前端和 LSP。
- 修改 CLI 后运行 `test.sh` 的 CLI 冒烟，而不只跑单文件编译。

## 8. 诊断

1. 优先使用已有错误码；已发布码不改语义。
2. 专用规则放在 `src/zxc.c` 的笼统规则之前，避免被 strstr 顺序误分类。
3. 同步 `src/errors.c`、`docs/errors.md`、`docs/reference.md`、LSP codeDescription 与 `test.sh` 码集守门。
4. 消息说明“错什么、为何错、怎么改”；能力边界不伪装成内部 compiler bug。
5. 负例钉住错误码；双前端错误路径对拍钉住首码一致。
6. 不在错误分支留下半初始化状态，避免连锁 `cyclic dependency` 等误导诊断。

## 9. LSP 与编辑器

- 先确认运行中的 `zxls` 是否真是新二进制。比较进程 StartTime 与 exe LastWriteTime；Zed 的 restart 不一定重新 exec。
- Windows 上运行中的 exe 被占用时，先改名旧文件，再构建/复制新文件；不要强删。
- 诊断以编辑器 buffer 为权威；只有磁盘 mtime 相对基线变化且 quiet 期满，磁盘才可覆盖 buffer。
- didChange 立即发送带 version 的空诊断；worker 发布同时校验文本与 version，过期快照丢弃。
- 批量 didOpen 仍需防止 stdout 管道互写死锁；不能把 didChange 的无条件清空机械搬到 didOpen。
- 影子文件必须与源文件同目录，并按严格文件名和 mtime 回收；避免 ACCESS_DENIED 与永久残留。
- 中间态文本、快速连续编辑、失焦保存、外部改盘、未保存 buffer、取消与关闭都要覆盖。
- 推断和补全必须做位置与作用域判定；裸标识符、循环变量、捕获和类型路径不能跨位置串名。
- 跨模块容器别名沿声明链展开到真实容器；解析别名中的 `@mod` 时以别名文件为 Document 上下文，不能借用消费者目录。补全、hover、跳转与来源定位共用该解析结果；导入别名按实例命名空间显示字段/变体，直接类型保持静态成员过滤。
- 依赖别名守门必须覆盖传递依赖、同文件别名链、别名文件相对导入、struct/union/enum，并断言跳转 URI 与声明偏移；不得只检查标签非空，也不能用末段同名搜索冒充真实来源。
- 已识别的 `const name = @mod("…")` 绑定优先按模块分类；模块无公开成员时保持空列表，不得回退到同名字段或容器。模块别名扫描检查标识符左右边界。
- 递归推断的 depth 必须贯穿 helper 回调；接受表达式或名字的 helper 不得把 depth 重置为 0/1。同时防御伪表达式与合法标识符环（如 `switch (op)` 的主语解析再次查找 `op` 捕获）。
- 用 ReleaseSafe 构建，确保栈溢出和 panic 可见；为“卡死”区分死锁、崩溃、无响应和旧进程。
- 运行：
  ```sh
  ZXLS_BIN=bin/zxls.exe python tools/lsptest.py
  ZXLS_BIN=bin/zxls.exe python tools/lspstress.py
  ```
- 协议测试后仍需真实编辑器黄金路径；无法实测时明确报告未验 UI。

## 10. 性能

1. 固定机器、工具链、输入规模、优化档与采样方法。
2. 保存修复前数据；使用现有 `bench/`、`tools/poolbench.zx`、`tools/logbench.zx` 或新增最小工具。
3. 先定位分配、锁竞争、惊群、拷贝、调度或后端形态中的真实瓶颈。
4. 正确性守门先通过，再比较性能；报告绝对值和相对变化。
5. 检查坏形状：worker 越多越慢、递归任务栈增长、热路径分配、关闭不唤醒。
6. 直觉方案被数据否定时回退，并把结论写入经验库。

## 11. 注释与断言同步

每次修改行为、API、内部表示、错误码或测试协议时，对受影响区域执行一次“文本+断言”审计：

1. 搜索修改的符号、函数、常量、AST 节点、错误码与测试名，阅读其周边注释和断言，不只搜索本次新增文本。
2. 更新描述现行行为的注释；删除过时解释、失效示例和“已删除某功能”之类的墓碑文字，不为历史保留误导性说明。
3. 对 `assert`、`test.sh` 静态断言、LSP 精确集合和测试期望逐项分类：
   - 仍有效：保留并确认确实覆盖现行行为。
   - 实现变化但目标仍有效：改为验证新路径，保持等价或更强。
   - 目标被设计撤销：删除，并在设计裁定记录原因；必要时添加替代守门。
   - 无法确定：先复现和查历史，不删。
4. 搜索旧名称、旧错误文案、旧 API 和旧格式，确认没有残留注释、文档或断言继续宣传旧行为。
5. 在最终差异中复核每次断言删除；只有设计变化能证明其目标消失时，删除才可接受。

## 12. 发版

仅用户明确要求发版时执行：

- 从 `src/zxc.h` 的 `ZXC_VERSION` 确认唯一版本源。
- 同步 `docs/reference.md` 版本行、`docs/manual.md` 落款与 README 文档表。
- 复核路线图，标记已完成项，不删除历史裁定。
- 构建三件套，跑全量回归、双前端、LSP 与适用压力阶段。
- 检查兼容性变更、错误码、平台能力、标准库 API 与编辑器加载要求。
- 提交和推送是单独授权动作，不因“发版”自动推断。
