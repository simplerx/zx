### §141 Pool.allocator() 可行性（用户提问）

- 结论：**可行，已实现**。`Allocator` 是普通结构体值，`ctx` 直接装 `(*u8)self`，
  另加模块级 `poolAlloc` / `poolFree` 两个转发函数。与 arena 不同：arena 的
  init 直接返回 Allocator、调用方手里没有对象，状态必须堆分配；Pool 本来就有
  `var pp`，零额外分配。

## §142 Pool.initThreadSafe + defer 求值顺序（用户：Pool 不是线程安全的吧，加个线程安全构造器）
- `std/pool.zx`（CRLF）：`Pool` 加 `guard: usize`（0=无锁），新增
  `initThreadSafe(gpa)`。锁字是单独从 gpa 分配的 `u64`，**不放在 Pool 值里**
  —— 值类型被 unwrap/复制/传进线程时不能复制出第二把锁。`guardTake`/
  `guardGive` 用 `std.atomic.atomicCAS/atomicLoad/atomicStore` 做 TTAS
  自旋锁（M58 起 mutex 运行时已收掉），首行反向 `module("std")` 取 atomic。
  `alloc`/`free`/`used` 改薄包装（lock → 私有 `*Impl` → unlock → 单一出口），
  `deinit` 归还锁字。既有三个池用例全过。
- 三条边界：backing 自己得线程安全（DebugAllocator 不是）、`deinit` 只能在
  线程收工后、只适合极短临界区。
- **撞出语言级 bug**：第一版写 `defer poolUnlock(); return impl();`，
  `--emit-c` 显示锁在 impl 之前就放了。根因 `src/backend.c` `gen_return`
  普通分支先 `run_defers(0)` 再把 `cxs()` 字符串塞进 `return %s;`，
  表达式到 return 才求值。修：统一先存 `_dr%d` 临时量再 defer 再返回；
  void 分支先发 `v;`。五个既有 defer/errdefer 用例输出不变。
  Pool 包装层仍用显式单一出口，不依赖这个修复。
- 实测：`pool-threadsafe.zx` 加锁 10/10 绿（约 0.12s/次），
  换成无锁 `init` 的对照组 3/3 段错误 exit 139 —— 守门确实能抓竞态。
- 守门 `tests/good/pool-threadsafe.zx`、`defer-return-order.zx`；
