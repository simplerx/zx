## M50 v0.50.0：捕获即返回值（if / switch 的糖）
- **语法**：`if (o) v;`、`if (o) v else 0`、`switch (u) { .some: v, .none: 0 }`——
  捕获名后面紧跟 `; , ) } ] else` 时，臂值就是捕获值本身（≡ `if (o) v t: { t: v; }`）。
- **实现**：解析期展开成「捕获 + NK_IDENT(捕获名)」，复用 M19 的「捕获 + 单值臂」，
  sema/backend 零改动。两处：src/parse.c parse_if_arm(implicit_ok) + parse_switch；
  bootstrap/parse.zx 同名函数（**位置必须逐字节一致**）。
- **bool 特判**（关键，否则悄悄改掉 idiom `if (a>b) a else b`）：check_if 里条件不是
  ?T/!T 且臂就是同名 ident 时 → n->name = NULL 退回普通表达式；名字又不在作用域 →
  报 "an `if` on a bool has nothing to capture" 并把该臂按 void 算（n->b=NULL），
  避免级联 "unknown identifier"。helper: arm_is_capture_value()（块包一层也算）。
- **switch 无类型可借力**：冒号后裸名字**一定**是捕获名，`1: K,` 的值是匹配值不是常量，
  逃生口 `1: (K),`。已写进 manual §8.1 第 19 条坑（唯一影响旧代码含义的地方）。
- **顺带修自举 bug**：bootstrap/parse.zx 的 parse_dot_brace 用 self.new(NK.tuple)
  （位置=第一个元素）而非 new_at(...,t)（位置=`.{`），嵌套 `.{ .a = .{1,2} }` 会岔 3 列。
  diff_ast.sh 现在 **72/72 全等**。
- **回归**：223 项全过（新增 tests/good/if_cap_value.zx、switch_cap_value.zx；
  tests/bad/if-sugar-bool.zx、switch-cap-value-mismatch.zx）。版本 0.50.0，spec v0.28，

## 性能体检 + 链接跳过优化（外部评估会话）

- **运行时与 C 打平（实测，非估计）**：同一 zig cc -O2、扣除空程序 12-14ms 进程创建基线后，fib 14.4 vs C 14.1、mandel 130.9 vs 132.0、mmat 92.1 vs 93.6、str 2.6 vs 2.0（ms）。结论：C 后端已到 C 的天花板，再优化 codegen 没有收益；-O3/-march=native/-fno-math-errno 对 mmat 全部无效（内存受限）。

- **已落地优化（src/main.c build_program）**：无单元重编且产物新于所有 .o 时跳过链接。zig cc 每次调用 ~200ms 固定开销（驱动启动 + lld + 自带 libc），占无改动重建的七成。判据挂在 njobs==0 上而不是纯 mtime——Windows st_mtime 秒级，同秒重编的 .o 与产物分不出先后。实测工程无改动重建 300→90ms（3.3x），单文件二次编译 300→87ms；删产物/改源码仍会正常重链（394/179ms），--lib/run/test 路径全过。

- **Allocator 无 ctx 是 std 分配类优化的硬墙**：sema_allocator_type 是 `{alloc: fn(usize)?*u8, free: fn(*u8,usize)void}`，没有 self/ctx，所以有状态的 arena 没法做成 Allocator（只能靠全局变量绕）。用全局 bump arena 顶替 std.heap.page 实测 json 80.4→55.1ms（-31%，校验和 840000/3599512485 一致）——证明 json 三成时间在分配器上，也说明 json.zx 注释里的 "arena 友好" 目前只能靠全局桩实现。建议 1.0 前给 Allocator 加 ctx 字段（破坏性，早改成本低）。

1. **惰性模块加载（sema.c）**：文件根上初值为 module("…") 的 const（及指向这类别名的成员链，如 std.zx 顶层 `pub const HashMap = map.HashMap`）不再急切解析（g_root_stmts 标记，check_block 进嵌套块时清除；g_fn_depth 判据不可用——模块检查嵌套在入口函数体检查内 fndepth=1）。配套修复：ns_member_symbol 现在先 ensure 再查 SK_NS（类型位置 `std.ArrayList(u8)` 曾报 "generic callee must be a function name"）。语义取舍：未被引用的 module() 不再触发加载，循环导入检测只在真实引用构成的环上触发（tests/bad/cycle-a/b 已改为真实引用循环）。效果：hello 11 TU → 3 TU，冷构建 1.5s → ~480ms（3.1x）。
2. **Allocator 加 ctx（破坏性，v0.58 直接改）**：类型变为 {ctx: ?*u8, alloc: fn(?*u8,usize)?*u8, free: fn(?*u8,*u8,usize)void}；调用点 a.alloc(a.ctx, n)。改了 sema_allocator_type、zx_alloc_page/{page_alloc,page_free}、zx_heapalloc/zx_file_read/fmt 的 C 侧调用，std 7 个模块 + bench/containers/poolraw + tests（arena/stdlib 的自定义分配器签名加 ctx、构造加 .ctx = null）。有状态 arena 现在可以做成真正的 Allocator 而不用全局变量绕。
3. **度量修正**：bench/run.sh 改 7 次中位 + 空程序基线扣减，计时用 $EPOCHREALTIME 去点变微秒（`date +%s%N` 子进程自身 ~30ms 会毁掉 80ms 负载的精度；`times` 是 shell 内建不能当函数名）。BASELINE.md 重写，附运行时 vs 手写 C 对照（已打平）。
4. **dev/release 分目录（main.c build_program）**：stem 加 -dev/-rel 后缀，`--release`↔`zxc run` 切换不再全量重编，回切 615ms → 73ms。
