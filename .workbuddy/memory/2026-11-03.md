## M48 zxls：模块解析链只有一条（vendor/ + deps 补全）
- **症状**：vendor/ 里的模块能编过，IDE 里 `ext.` 补不出成员，跳转/hover 同病。
- **根因**：LSP 有两处各自回退目录的循环（moduleDecls 补全 / resolveModuleFile
  跳转 hover），都只查「文件所在目录 → 工程根」；编译器 module_load 查「文件
  所在目录 → setup_search_paths（vendor → deps）」。vendor/deps 从没进过 LSP。
- **修法**：`g_mod_dirs`（initialize 时算绝对路径：root/vendor、root/<dep>）+
  `modDirsInto()` 统一拼顺序 → moduleDecls 与 resolveModuleFile 都用它。
  路径语义两个方向：LSP 自己用绝对路径（deps 相对工程根拼），zxc 子进程用
  相对语义 → 把子进程 `.cwd` 钉在工程根（`childCwd()`）。
- **代价**：改 zx.json deps 后要重启语言服务器（不每次重读）。
- **回归**：tools/lsptest.py 10 → 14 项（vendor 成员/前缀/deps/跳转 vendor），
  首次并入 test.sh 2.6 节（自己编 zxls 到 $TMP.zxls.exe，不碰被 Zed 锁的
  bin/zxls.exe）。217 + 6 CLI + 14 LSP 全过。
- **环境坑**：本机 bash 工具的子进程 env 被沙箱裁过（无 TEMP），zxc → zxfe
  会退到 C:/WINDOWS 写 .zxfe-*.ast 失败 → 诊断全空。测 LSP 诊断别在这个
  shell 里下结论。
