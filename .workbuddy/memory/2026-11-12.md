## 并发解法方向（调研结论，未实现，待用户拍板）
- zx 已具备**无函数着色**：任务就是普通 `fn(usize) !usize`，await 是库方法，
  取消 = `error.cancelled` 走 `!T` 传播链。与 Go / Java Loom 虚拟线程 /
  Zig 0.15+ 移除 async-await 改用 std.Io 的方向一致，**不要推翻**。
- 缺的是**结构化并发**（Trio nursery / Swift TaskGroup / Kotlin coroutineScope /
  Java JEP 525 StructuredTaskScope / C++ stdexec async_scope）：任务生命周期没绑词法
  作用域，awaitAll 不聚合错误，取消没有父子树，没有 deadline/timeout/select，
  失败不自动取消兄弟任务。
- 建议沿用 M58「Task 是 std/task.zx 里的普通 struct + extern 调 C 运行时」路线，
  加一个 `Scope` 库类型（不是新语法、不进编译器类型系统、不动调度器核心）：
  spawn 登记父子、`join` fail-fast 返回首个错误、`defer sc.close` 或 `withScope`
  自动 cancelAll+awaitAll。阶段 2 补 deadline/select/Chan(T)/异步 I/O；
  长期做静态防数据竞争。守门照 §92 的做法：确定性 expect-output + 20/20 压测。

## 阶段 1：Scope 结构化并发落地（用户 10:24「继续」拍板，已实现，未提交）
- **API**：`std.task.Scope`（库 struct + `extern fn zx_sc_*`，沿用 §94「Task 不进
  类型系统」路线，不加语法）：`Task.scope()`、
  `Task.withScope(body: fn (*const Scope) !usize) !usize`、
  `Scope.spawn/join/await/cancel/close`。`withScope` 自己登记 `defer sc.close()`。
  zx 无闭包，body 拿外部数据用全局 var 或 `Task.fromId(t.id)`。
- **最重要的裁定：退出必清理靠 `defer`，不要在 C 里维护 active_scope 栈**。
  正常返回与 `!T` 错误传播都展开 defer → 父任务被 cancel 时错误上冒触发
  `sc.close()`，整棵子任务树被级联取消。不必改 `zx_task_cancel`。
- **运行时**：`ZxTask.sc` 打标、`ZxScope` 记 ids[] + first_tag/ret + failed/closed。
  `zx_task_finish` 首个错误 → `zx_sc_cancel_all` 即时 fail-fast；`join` 逐个
  await 回放**首个**错误（全成功返回首个 spawn 任务的返回值）；`close` =
  cancel 全体 + 等全体 + 幂等，封口后 spawn 返回 null。
- **三个必须记住的坑**：
  1. **循环回边注入的 return 必须展开 defer**：`emit_loop_cancel_check` 改用
     `{ run_defers_m(0, 1, NULL); return (ErrT){…}; }`。defer 是编译期展开、
     只有 `NK_RETURN` 分支调 run_defers；上轮那句裸 return 让取消路径漏掉
     **全部** defer，Scope 的自动 close 在这条路径上完全失效。
     守门 `task_scope_cancel.zx` 的 `interrupted:1`（漏了会跑满 LIMIT）。
  2. **成员登记必须在 `zx_ready_push` 之前**（入队后 worker 可能立刻 free(t)），
     且 `done` 的发布必须推迟到 finish 的 scope 段**之后**（否则 close 看到
     done 就 free(sc)，finish 里还在访问 sc → UAF）。
  3. **句柄仍绝不复用**（上轮结论）。scope 壳不随 `sc.close` free，挂
     `s->sc_list` 由 `zx_task_close` 统一回收，避免并发 spawn 拿悬垂指针。
- 漏取消窗口：登记 ids 之后、入队之前兄弟可能已失败，`cancel_all` 遍历时
  t 还没发布。两处补判：登记时 `doomed = sc->failed`、入队前再查
  `sc->failed || sc->closed`。
- 边界同 §94：`scope()/join()/close()` 创建者串行、spawn 可并发；defer 顺序
  必须让**作用域先于实例**关闭。**阶段 2 未做**：deadline/timeout、select、
  类型化 `Chan(T)`、`std.io` 阻塞调用改成停靠任务、静态防数据竞争。

## 架构回转（用户 13:0x 拍板，§123）：撤销 offload / 统一 Task API / 原语层抽取
- **用户三条**：zx 要「简洁、透明」，默认 offload 不要；io 恢复纯同步，真要
  异步显式「task + io」；「C 原语层抽取 + 调度逻辑上移到 zx + std 类型收敛」
  一次做完、把 task 做成统一对外 API。补充「这些都做内部实现吧」= 内部
  struct / 原语一律不暴露。
- **offload 全删**：`ZxIoJob` / `zx_io_hook` / `zx_io_run` / `zx_io_*_sync` /
  `ZX_HAS_IO_RUNTIME` 段 / `zx_task_io_offload` / `zx_task_new` 里的注册。
  `emit_io_runtime` 恢复 `fread/fwrite/fseek/ftell/fclose/fflush` 同步包装。
  理由：偷偷起线程 + 停靠纤程与「透明」相反；真异步 I/O 要 CPS/async，
  会丢无函数着色。
- **统一 API（std/task.zx 只 pub Task）**：Scope/Group/Chan 全部退化成
  `usize` 句柄；`t.scope/scopeSpawn/scopeJoin/scopeJoinTimeout/scopeClose`、
  `withScope(fn (*const Task, usize) !usize)`、`Task.group/groupSpawn/groupWait/
  groupClose/groupRun`（关联函数，组与实例无关）、`t.chan/chanSend/chanRecv/
  chanTrySend/chanTryRecv/chanClose`、`Task.SEL_AWAIT/SEL_RECV` 关联常量。
  所有 `extern fn` 不 pub（模块顶层默认私有）。
- **语言事实（写库前必看）**：容器方法**不能泛型**（E0701）；自由泛型函数
  `fn (T: type, …)` 可以。所以 `Chan(T)` 没法做成 `Task` 的泛型方法，最终
  载荷统一 `usize`，大值由调用点 `(usize)v` 的 castable 表挡（bad/chan-wide
  仍守 E0300）。另一个坑：struct 里的关联常量若引用**同文件模块级 const**
  会生成 `task_XXX` 未定义符号（B1003），直接写字面量最稳。
- **C 原语层抽取**：新增 `zx_rt_cpu_count` / `zx_rt_thread_spawn` /
  `zx_rt_backoff` / `zx_rt_fiber_make` / `zx_rt_fiber_drop`；`zx_now_ms`、
  `zx_lk`/`zx_cv_*`、`zx_task_switch_to`、`zx_task_rootctx`、`__thread zx_fb_cur`
  归入同一原语层。生成 C 里加了「原语层 / 调度层」分段注释；
