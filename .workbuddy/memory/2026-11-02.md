## M10（2026-11-02）`{any}` 结构展开 + switch 穷尽性独立报错 + 多序列 for 静态长度

**`{any}` / 默认 `{}` 的结构展开**（`src/backend.c`）
- 描述符驱动：每个用到的类型生成一个 `ZxAnyType`（kind / name / size / sign / n /
  fields / elem / aux_off / aux_size / tags / names / is_str），字段偏移用 C 的
  `offsetof` 算，描述符之间用**下标**互指 → 整个 `zx_at[]` 一次性定义，递归类型
  （`Node` 里的 `?*Node`、`Node` 里的 `[]Node`）不需要前向声明。
- 运行时的 `zx_any(sink, desc, ptr, depth, mode)` 是唯一实现；编译期路径
  （`ex_print`）发 `zx_any_stdout(&zx_at[i], &值, mode)`，运行时路径把描述符塞进
  `ZxFmtArg.ty`，`zx_fmt` 遇到 `{}` / `{any}` 调同一个函数。两条路输出不可能分叉。
- 取右值地址：`&(T[]){ e }[0]`（数组复合字面量是左值）。`(T){ e }` 不行——那是在
  初始化第一个成员。
- 输出格式：`Point{x: 1, y: 2}` / 元组 `{1, "two"}` / `Shape{circle: 2.5}` /
  `Raw{i: 1 | f: 1.4e-45}` / `null`、`some(5)` / `ok(7)`、`err(error(3))` /
  `[10, 20, 30]` / `null`、`0x…`（指针不跟进去）；`{any}` 比 `{}` 多两样：枚举打
  `Color.blue`、`[]u8` 打带引号带转义的 `"a\tb"`。深度 >8 打 `...`，切片 >64 个
  元素打 `, ...`。
- 踩坑：枚举的变体数一度被记进 `nf`（字段数），生成了空的 `zx_af_*` 数组 + `(null)`；
  分成 `nf` / `nt`。
- 驱动顺序：泛型实例的函数体在 `emit_fmt_runtime()` 之前生成 → 把 bin/fmt/any 三个
  运行时都挪到实例循环**之后**（否则只有实例里用到的运行时会漏发）。
- 没有描述符时发一个 `zx_any` 空壳，避免 `{fmt 变量, 只传整数}` 也拖进整台打印机。

**switch 穷尽性独立报错**（`src/sema.c`）
- 抽出 `switch_coverage(n, s, &has_else, &nwant, missing, cap)`，`check_switch`（自身
  完整性）和 `switch_ends`（到达性）共用一份判据。
- 纯语句形式的 switch 漏变体也报：`switch on `Color` is not exhaustive: missing
  `.blue`; add an `else` arm`；`?T`/`!T` 报 `.none` / `.err`，bool 报 `false`（不带点）。
- 泛型实例重复检查 → 按 (line, col) 去重（`g_sw_diag`）。
- 整数 subject 永不要求穷尽；普通（无标签）联合体不算变体集合。

**多序列 for 的静态长度**（`src/sema.c`）
- `seq_len()`：范围 `0..3`、定长数组视图 `arr[0..]`（长度来自 `*[N]T`）、数组字面量
  `&.{…}` 都算得出来；切片的 `s[0..]` 只有 ptr+len，算不出来 → 不参与比较。
- 于是 `for (a[0..], b[0..])` 现在真能报 `3 vs 2`（规格 §8.3 原来只是"声称"）。

**测试**：`tests/good/any.zx`（14 行输出，覆盖结构体/元组/切片/可选/错误联合/枚举/
带标签与普通联合体/字符串转义/嵌套/运行时 fmt/std.format）、`tests/good/seqs.zx`；
反例 `tests/bad/switch-missing.zx`、`tests/bad/for-slice-len.zx`、`tests/bad/fmt-verb.zx`。

顺带补的：格式动词与实参类型不符现在是编译错误（`check_fmt_verb`）：`{s}` 要切片、
`{c}`/`{b}` 要整数、`{d}`/`{x}` 要整数或浮点——以前会生成一段编不过的 C。

## M11：泛型类型别名 + 结构体方法

上面那个坑当场修掉了，连同"struct 体里的方法"一起做完。`sh test.sh` → **102 项全过**

**泛型类型别名**（`src/sema.c`、`src/backend.c`）
- 后端 `gen_decl_inner()` 开头 `if (t->kind == TY_TYPE) return;`——类型值只在编译期
  存在，C 里没有对应物。
- 类型名改由**构造式**决定：`name_type_from_call(call, result)`，在 `instantiate_type()`
  末尾与 `check_call()` 的 `TY_TYPE` 分支都调。理由：同一实例被多处 `const` 起名时，
  叫哪个名字取决于检查顺序——那是巧合不是名字。于是打印 `Pair(i32){a: 1, b: 2}`。
- 值参数也进名字：`arg_ct()` 先 `lookup`，`ty != TY_TYPE && ct` 就按值取（`List(T, cap)`
  里的 `cap` 解析出来是 `NK_TYPE_IDENT`，但它其实是 `usize` 值），实例名从
  `List(i32, ?)` 变成 `List(i32, 2)`。

**方法 = 第一个参数是接收者的普通函数**（`src/ty.h`、`src/ty.c`、`src/sema.c`、`src/backend.c`）
- `Type` 加 `Method *methods; int nmethods;` + `ty_method(t, name)`。
- `resolve_struct_body()` 末尾遍历 `NK_FN` 成员：`resolve_fn_type()` 拿签名 → 首参必须是
  `agg` 或它的指针 → 禁止 `TY_TYPE` 参数 → 禁止与字段重名 → 入表 → `schedule_body(it)`。
  报错按 (line, col) 去重（`g_mrecv_diag` / `mrecv_dup`），因为泛型实例化会重复检查。
- 体作用域里预挂 `Self`（`SK_CONST` + `ty_type(agg)`）——泛型体里不用重写 `T, cap`。
- `check_field()` 四个分支（`TY_TYPE` 静态成员 / `TY_PTR` 穿透 / `TY_STRUCT` / `TY_UNION`）
  都加方法查找，命中则 `n->inst = m->fn; return m->fnty;`。
- `check_method_call()`：`Type.f(p, a)` 按普通函数；`p.f(a)` 自动把接收者补成 `items[0]`。
  接收者是值而方法要 `*Self` 时包一层 `&`，要求 `addr_ok()`（IDENT/FIELD/INDEX/`*p`）
  且 `lvalue_mutable()`；已经是指针的只交给 `coerce` 处理 const 加减。

**三个连带修的坑**
- **静态成员要两遍布局**：`const ZERO = Vec{…}` 的初值要构造 `Vec`，而字段表还没挂好。
  第一遍只占位（`it->index = k`），挂好 `agg->fields/nfields` 后再 `ensure()` 回填类型。

- **泛型实参在 C 里没有变量**：`Symbol` 加 `ct_bind`，`specialize_raw()` 给前 nbind 个

## M11 补：匿名字面量由期望类型驱动

写文档时发现 `var v: Vec = .{ .x = 1 };` 直接报
`expected `Vec`, found `struct{x: comptime_int}``——这不是泛型别名的问题，而是
`NK_ANON_STRUCT` 根本不看 `expect`。既然规格 R6 写着"期望类型驱动"，这就是个 bug。

- 抽 `check_lit_fields(n, t)`：`check_struct_lit` 解析出 `t` 后调它，`NK_ANON_STRUCT`
  在有期望类型（`TY_STRUCT`/`TY_UNION` 且有字段）时直接调它，`n->ty = expect`。
  字段匹配 / 缺字段 / 联合体只准一个成员，两条路径共用一份。
- 编译期那一侧也漏了：`ct_struct_lit()` 只认 `n->a`（具名字面量的类型节点），
  匿名的没有 `n->a` → 回落到 `n->ty`；`ct_eval` 的 switch 里也没有 `NK_ANON_STRUCT`，
  补上。于是 `const one = .{ .name = "ann" };` 能折成静态初值。
- 验证：`var p: Person = .{ … }`、`return .{ … }`、`take(.{ … })`、顶层
  `const one = .{ … }` 全部跑通；`tests/good/generic-alias.zx` 加了一行
  `var l2: IL2 = .{ .buf = buf, .len = 1 };`（输出 `anon full=false len=1`）。
- 文档：规格 §4.2 补这条规则，decisions 新增 §33，README 的待办里删掉这条。

## M12：枚举成员 + 标准库 + 选择性导入

用户要求三件一起做完：「enum 体里的 fn / const 补上」「标准库补到能写程序」

**枚举体成员**

- 编译器只留 5 个内建名（print/println/format/heap/file），由 `std_builtin()` +

## M13：撤销 import、捕获名收紧、每模块一个 .o、std.HashMap

用户要求（原话）："选择性导入不要现在的 import 方案，使用 `const std = module("std")`；

**写它逼出的三个真 bug**
1. **`fill()` 把"已全部交付"的缓冲当残段**：`start == end` 时不该 compact，
   应直接 `start = end = 0`（否则 `chunk()` 每块都会把 cap 翻倍）。
2. **`if` 捕获名是只读的**：`if (init()) got { got.owned = true; }` 报
   "cannot assign through a read-only path" → 先 `var r = got;`。
3. **`snap_scope()` 冻结模块符号表**：待检查函数体存的作用域快照把 `first` 冻在
   调度那一刻，而编译器内建是 `std.zx` 解析完之后才并进 std 作用域的 →
   `std.zx` 自己的函数体看不见 `print`/`io`（以前没用过所以没暴露）。
   修法：`Scope` 加 `is_module`，模块级作用域快照直接引用同一个 Scope。

## M28（feature/union-enum 分支）: switch 捕获
- 语法：pattern: [IDENT] body，IDENT 后跟 `{` 才是捕获（臂标签是 IDENT+`:`）；捕获仅配块臂（cap 值 vs 裸表达式臂无法区分）
- 捕获类型一条规则：联合体=变体载荷（按模式名查字段，不是捕获名——踩过一次）、?T .some=elem、.none 报错、!T .ok=elem/.err=ty_error()、枚举/标量=主语本身；仅单模式臂，else 拒绝
- backend gen_switch 重构：主语聚合或有捕获 → 先落 _swN，头部 switch (_swN.tag)；修掉 ?T/!T/union 主语发 switch(struct) 的潜伏 bug（sema 早放行、后端从未支持、无测试覆盖）
- C 细节：hoist 路径 switch 要自己补括号（exs_cond 自带）；switch-bool warning 无害
- 值位置+捕获没做（块臂靠收割交值，动它要单独设计）；类型模式同留
