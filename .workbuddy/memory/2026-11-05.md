## FFI 补全（M24 后半）：extern struct / extern var / @link
1. **extern struct / extern union**：`const Vec3 = extern struct { … };`——类型前缀（parse_type_prefix + parse_primary 类型即值入口），is_extern 落节点、AST flg 位 2 序列化。sema `check_c_able` 逐字段校验：`?T`（带标签 optional）`[]T` `!T` 元组 方法 静态成员 默认值 全拒；`[N]T`（写作 `*[N]T`）展开成 C 内联数组 `char name[64]`（ty.c 的 ext_array_field 让 @sizeOf/@offsetOf 按内联算——普通 Zx 结构体的 *[N]T 仍是 8 字节指针，别动全局 ty_size 否则结构体拷贝按错大小 memcpy）。嵌套聚合必须也是 extern。fn 指针字段直接可用。实测 kernel32 GetLocalTime 年月日正确。

4. **@offsetOf** 补了 sema 侧实现（backend 早就有 case，T,T 布局在 ty_size 里顺带算好）。

## M26：`_ =` 丢弃 + @embedFile + 格式化 spec + `?*T` 无标签 optional
1. **`_ = expr`**：check_assign 顶部拦截（左值名 "_" 且无 sym），右值 void 报 E0306；后端走临时槽位 gen_value。`_ = f()` 之前不存在。
2. **@embedFile**：编译期读文件进 `n->str/n->str_len`，ct_eval 返回 val_str（R1 const 依赖），后端发 `((ZxSlice_u8){...})`。路径相对当前模块（path_dup_dir+path_join）。check_builtin 里 read_source/path_dup_dir/path_join 需前置声明。
3. **格式化 spec 补全**：`{[idx][verb]:[fill][align][width][.prec]}`。冒号分割同步进 sema 的 check_fmt_args（E0802 校验器要认得 `{:>8}`）。空格填充映射 printf 旗标（零成本）、零填充+右对齐用 '0' 旗标，自定义填充/居中走 zx_fmt_pad/zx_fmt_pads 助手（g_need_pad 条件发射，含 stdarg.h）。字符串默认左对齐、数字默认右对齐。精度上限 256。
4. **`?*T` 无标签 optional（ty_opt_flat）**：null = 0 指针，C 表示直接 `T*`，sizeof = 8（`?*i32` 16→8；自引用 `next: ?*Node` 节点不多占标签字节，Node=16）。布局全在 ty.c（ty_size + align）/backend.c（ctype/条件判定/.tag→`!=0`/.payload 直发/NULL/UNDEF/NK_TRY 合并分支/orelse/while-unwrap/val_init/any_desc=AK_PTR）；sema 28 处基本纯语义零改动。运行时发射器四处用旧布局（zx_page_alloc/zx_heapalloc/zx_file_read/zx_format）同步改指针语义；zx_unwrap flat 版参数类型用 ctype(t)（tn 名无 typedef）。
5. **修复既有 bug**：直接 println 字符串字面量（及 typeName/file/@embedFile 等内建直发点）ZxSlice_u8 typedef 未声明 → 全部补 ensure_type。
6. 语法备忘：**switch 臂块后必须有逗号**（`.some: p { … },`），臂后无逗号报 E0202 "unexpected token in top-level declaration"（f7 排查半天其实是这个）；**匿名 fn 字面量不能当值**（`let sum = fn…` 报 "expression node reached the C emitter"，函数提模块级）。`try ?T` 要求所在函数返回 `!…`（try_thing 改 !void）。
7. 回归 251 passed / 0 failed（新增 tests/good/optflat.zx 全路径探针：orelse/switch 捕获/while-unwrap 链表求和/try/null if）。docs/manual.md 布局表加 `?*T` = 指针宽度一行，§3.9 注明唯一无标签例外。提交 06577ec。
- 顺手项未做：struct 字面量字段位内建调用、`(T)@expr` 括号两个解析毛刺。

## M27：switch 臂终结符 `,` → `;`（v0.29）+ cast 修 `@`（用户裁定）
1. **用户拍板**：三毛刺一起清，臂终结符改 `;` 不留 `,`。实测"struct 字面量字段位内建调用"是伪问题——真凶只有 cast：`can_follow_cast` 缺 `TOK_AT`，`(u16)@sizeOf(...)` 被当括号表达式解析，任何位置都要 `((u16)@...)`。加 `TOK_AT`（`@` 永远不是中缀运算符，零歧义），双端（src/parse.c + bootstrap/parse.zx）各一行。
2. **新臂语法**：每臂以 `;` 结尾（含末臂）；`,` 只作同臂模式并列（不再需要 starts_pattern 消歧，只留作校验）；隐式捕获糖 ends 判据 switch 侧 `;`/`}`。EBNF/manual/guide/spec/decisions §95 同步；tree-sitter grammar.js 改后 `npx tree-sitter generate` + build-wasm.sh 再生成。
3. **迁移方法论（可复用）**：新编译器当检查器，报错行列即待改位置逐文件修。三教训：① **错误恢复后的第 2..n 条报错不可信**——第一处报错后解析状态错乱，后续行报错位置是垃圾，只信第一条、不是臂错就停（首版脚本全信导致 char 多模式 `'a','b'` 被级联误伤成 `'a';'b'`）；② **编译器列号按字节、Python 按码点**，`'中'` 一出现列错位，脚本必须按字节（open "rb"、索引 s[c]）；③ 末臂省略终结符的报错落在 `}` 上，插入而非替换。
4. zfe 自举链注意：改 bootstrap 源后旧 zfe 解析不了新语法 → `rm bin/zfe.exe && sh build.sh`（自动走 --fe=c）。
5. 回归 253/0（新增 cast_at.zx）；demo/ffi OpenGL 全链路复编通过。提交 0e7d403。

## M62：诊断可点选（LSP range）+ 错误码目录

## M63（续 M62）：诊断的"下一步"——兜底修法 + 可点的错误码（v0.62.0）

**目标**：M62 让诊断指得准，这一轮解决"看到之后怎么办"。

**做法**：

  **每个码只印一次**（`g_fix_shown[16][8]` 记已印的码）——同类错误连成一片

  `capabilities.textDocument.publishDiagnostics.codeDescriptionSupport` 时发**

2. `error.` 点不出码名 → zxls 文本层补全：扫工作区 `error{…}` 块 +

3. 集合能不能合并 → 能了：NK_ERR_SET 定型时，字面量里的名字解析到

  永远"子集"，E0901 就哑了。
