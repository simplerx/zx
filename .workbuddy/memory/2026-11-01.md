## Zx 编程语言规格（v0.1）

依据 `plan` 文件（简洁/高效、类 C 与 Zig 的系统级语言）完成了完整语言规格。

产出（`spec/`）：
- `zx-spec.md` — 主规格：词法、16 类类型、变量、表达式、控制流、函数、泛型、模块、内联汇编外的全部语义规则 R1–R9
- `zx.ebnf` — 完整 EBNF 文法
- `examples/{hello,types,control,generic,errors}.zx` — 覆盖全部特性的示例
- `decisions.md` — 6 处 plan 内部矛盾 + 裁决、6 处必须补的语法、5 项建议扩展、实现路线

关键设计裁决：
- `*T` 是唯一指针类型，带编译期长度 N：`*T ≡ *[1]T`，数组用 `*[N]T`，运行时长度用 `[]T`
- `*` 前缀 = 取地址，`.0` = 解引用，`.` 自动穿透一层指针
- `?T` = `{tag: bool, payload}`（null 就是 false）；`!T` = `{tag: u16 error, payload}`（0 = 无错误）
- 带标签联合体 = 成员为 `{tag, Type}` 元组的 union，`?T`/`!T` 是它的语法糖
- 参数/循环捕获是"只读运行时槽位"，其 comptime 性由调用点决定（解决 "const 必须编译期" 与 "函数收运行时参数" 的矛盾）
- 作用域即值：块的值 = 末尾表达式或 `break e`；`return e` 是 `break e` 的糖
- if/while/for 都是表达式，`else` 在循环里表示"正常跑完"

待用户拍板（decisions.md F）：
1. const 是否严格到"只能编译期"（我建议加 `let` 补运行时只读）
2. `*[N]T` 与「声明即分配」规则（R9）还是改成 `[N]T` 值数组
3. 参数例外规则
4. switch 是否进 v0.1（建议要）
5. defer 是否进 v0.1（建议要）
6. 后端先 C 还是 LLVM

下一步（未开始）：lexer / parser / 类型检查 / 编译期解释器。

## Zx 规格 v0.2（用户裁定落地）

用户明确裁定，规格已整体改写：

- 取地址 `&`，`*T` 只是指针类型构造子（`*` 不再取地址）
- **数组就是纯指针 `*T`**：元素个数不进类型、不进运行时表示；`*[N]T` 降级为编译期长度注解（同一类型，8 字节）
- 数组字面量 `&.{0,1,2}`；**元组字面量是 `{0,1,2}`**（差一个 `.`）；`.{…}` 是"强制字面量"标记
- `.len`（元素数）/ `.size`（字节数）/ `.ptr` 是编译器字段，长度已知时全是编译期常量；`len`/`size`/`ptr` 因此不能当结构体字段名
- 新增 `let` = 运行时只读（`const` 仍是编译期，语义未变）
- 联合体 Zig 风格：`.成员 = 值` 构造、`switch` + `|x|` 分派且要求穷尽；**`if (u) v { }` 省略竖线**直接写捕获名
- `{…}` 消歧规则：从 `{` 扫到匹配 `}`，顶层有 `;` 或声明 → 块，否则 → 元组；强制块位置（函数体/if 体/类型体）不受影响
- 词法：浮点必须有整数部分，`.` 后的数字永远是下标（`t.0.0` 合法）

文件状态：`spec/zx-spec.md`、`spec/zx.ebnf`、`spec/decisions.md`（改写为"裁定记录"，每条含代价）、`spec/examples/{hello,types,control,generic,errors,literals}.zx` 全部对齐 v0.2。

仍待定：后端 C vs LLVM（建议先 C）、`defer`、`for` 带下标、格式化输出。

## Zx 规格 v0.3（第三轮裁定）

用户定了四件事，规格/文法/示例已全部对齐：

- **后端先出 C**（M4a C，M4b 再看 LLVM）；理由：最快端到端、`?T`/`!T` 布局就是普通 struct
- **`defer` 进 v0.1**：离开所在块时执行一次，LIFO，退出时求值，不产生值；`defer` 体内禁 break/continue/return；陷阱是 `return` 值先算、defer 后跑（所以 `defer free(buf); buf` 会返回悬垂）
- **`for` 只吃切片 `[]T` 和整数范围 `lo..hi`**（左闭右开），绑定名不带竖线：`for (0..n) i`；数组要写 `arr[0..]`，元组/枚举不是序列
- **数组类型是 `*[N]T`，N 进类型**（推翻 v0.2 的"长度只是注解"）：`*[3]i32` ≠ `*[4]i32` ≠ `*i32`，表示仍是 8 字节地址；`*[N]T → *T`、`*[N]T → []T` 隐式，`*T → *[N]T` 必须显式 `(*[N]T)p`

关键点：`.len`/`.size` 现在有确定来源（就是 N），语义分析不需要"长度证据"旁路。这条推翻 v0.2 时我在 decisions §2 里写清了为什么第一版是错的。

文件：`spec/zx-spec.md`（~900 行，v0.3，含 §8.6 defer）、`spec/zx.ebnf`、`spec/decisions.md`（13 条裁定）、6 个示例。剩余待定：格式化输出、`errdefer`、`for` 双绑定。

## Zx 规格 v0.4（第四轮裁定，当前版本）

用户又定了五件事，全部落进规格/文法/示例：

- **`{x}` 是元组，不是块**。块的值只能由 `break v` 产生，默认 `{}`；末尾表达式是语句，不产生值。`{x,}` 与 `{x}` 等价。判定只看花括号顶层有没有 `;` 或声明。
- **连锁**：函数体必须 `return`（`fn f() i32 { 1 }` 报错）；`if` 的块臂不再有值 → 新增 **`=>` 表达式臂**（`if (c) => a else => b`），与 `switch` 统一；`if`/`switch` 的块臂是**透明**的 break 目标，`break` 穿过去落到外层循环。
- **标签作用域**：`tag: { … }` / `tag: for …`，`break :tag v;`、`continue :tag;`。标签在语句和表达式位置都可用（`let x = t: { … };`）。break 目标表见 spec §8.5。
- **`?T` / `!T` 布局：payload 在前、tag 在尾部**（`{payload: T@0, tag}`）。理由：`&x` 即 `&payload`，`*?T → *T` 零偏移重解释，不会因对齐静默错位。`sizeof(?T)=align_up(sz(T)+1, align(T))`。
- **`for` 多绑定**：`for (xs, 0..) x, i`、`for (a, b) x, y`；序列数 = 绑定数；必须等长（编译期已知则编译期报错）；`lo..` 省略上界只在多绑定时合法，上界取公共长度。
- **格式化**：`fmt` 是编译期常量 → 编译期展开成直接输出序列；是运行时值 → 回落运行时解析器，语义一致。

教训：`{x}` 定成元组后，不能再有"末尾表达式即块值"，否则两者冲突。取舍写在 decisions §13，连锁代价也写清楚了。

文件：`spec/zx-spec.md`（~1150 行）、`spec/zx.ebnf`、`spec/decisions.md`（17 条裁定）、`spec/examples/*.zx` 6 个全部按 v0.4 重写。`tools/patch_v04*.py` 是本次批量改写的临时脚本，已删。

## M4 完成：编译期求值 + 泛型单态化

新增 `src/val.h`/`val.c`（值模型），`src/sema.c` 追加两节（编译期求值 + 泛型实例化）。

关键设计：
- **Value**：`V_INT/V_FLOAT/V_BOOL/V_STR/V_TYPE/V_AGG/V_FN/V_PTR`，只分配不回收。
  `V_TYPE` 让"类型是一等值"落地；`V_PTR{base,off}` 表示 `&.{…}` 物化的静态数组。
- **折叠点在 `check_expr` 包装层**：`check_expr_raw` 出类型，包装层顺手 `fold()`。
  算不出来就返回 NULL，等同于"运行时算"。不需要 comptime 关键字。
- **解释器跑在已检查的树上**：ident 都有 sym，执行只写 `Symbol.ct`。控制流用
  `CtFlow{kind,val,label}` + 全局 `g_ct_flow`（表达式里的 return 往上冒）。
- **泛型 = 编译期函数 + 克隆**。`specialize()` 克隆整棵 fn 树，于是里面的
  `struct{…}` 有独立节点身份 → `ty_agg` 天然分出不同类型，不需要类型替换表。
  顺序必须"先绑定参数、再 resolve_fn_type"（签名里就有 `List(T)`）。
  实例表按 `(fn节点, args)` 用 `val_eq` 缓存，保证类型身份稳定。
- 泛型 fn 的签名延迟解析，占位类型 `ty_generic_fn() = ty_fn(NULL,0,NULL)`（ret==NULL 是特征）。

踩过的坑（都已在代码里注释）：
1. `same()` 里 `a->ret` 为 NULL 时解引用 → 段错误；加 `if (!a || !b) return false`。
2. 标识符节点不能缓存 `ct`（var 会变）；循环体每轮要 `ct_clear`。
3. `fold` 里必须同时隔离 `g_ct_stuck` 和 `g_ct_flow`，否则一次失败/一次 return 会永久毒化后续折叠。
4. `@compileError` 不能在检查函数体时报错 → 改为执行到时才报；并且**编译期已知条件的 if 只检查真会走的那一支**。
5. 名字 buf 忘了 `'\0'` → `Type.name` 读越界，报错信息里出现乱码。

- **打印**：格式串必须编译期已知；`{} {N} {d} {x} {b} {s} {c} {{ }}` 全部展开成 printf，

### R1 强制：先要视图，才敢报错

直接加报错会把 `const mptr = &arr;` / `const head = str[0..2]` 全打挂，所以先补
**编译期视图折叠**（新决策 §19）：

- 切片的编译期值 = `V_PTR { base(最底层的 V_AGG/V_STR), off(元素下标), nitems(可见长度) }`。
  `s[lo..hi]` **不复制数据**，只挪起点、改长度；字符串切片产一个短 `V_STR`。
- `&x` → `V_PTR{base = x 的编译期值}`；对视图再取地址 → 返回视图本身（不套两层）。
- `ct_field` 统一处理 `.len`/`.size`/`.ptr`/`.N`：`*[N]T` 的 `.len`/`.size` 都取 N，
  元组的 `.size` 走 `ty_size_relaxed`，切片的 `.len` 读 `nitems`，字符串按字节索引。
- `ty_size_relaxed`/`ty_align_relaxed`：comptime_int→4、comptime_float→8，
  tuple/struct/union/opt/err 递归（err 的 align ≥ 2）。给"类型还没定尺寸时算大小"用。

**`g_ct_exec` 闸门**（新决策 §20）：读 `var`/参数/捕获**只在编译期求值器真正在跑时**
才出值；普通表达式里一律"没有编译期值"。否则 `const k = runtimeVar + 1` 会悄悄
折成一个过期值。实现是 `ct_run_raw` + 外面包一层 `ct_run` 自增计数。

**递归闸门**：顶层 `fn` 符号现在带 `ct = val_fn(...)`（为了 `const FIVE = add(2,3)`），
于是检查 `fib` 自己的函数体时会把 `fib(n-1)` 折进去，`fib(-1) → fib(-2) → …` 直接
把编译器栈炸掉（退出码 127）。加 `g_ct_stack[]` + `g_ct_checking`：**正在检查**函数体时
拒绝折叠已在栈上的函数；**执行**阶段（`ct_run`）不设限。另加 `g_ct_nstack > 100` 兜底。

R1 报错落在 `ensure_raw`：
`const 'k' must be computable at compile time (R1); this initializer needs runtime values`
（`NK_MODULE` 初值、类型值 `type_val`、`TY_INVALID` 三种情况放行）。

### `pub` + 真多文件

- 关键字 20 → **21**；`pub` 只允许文件作用域（函数体里写 `pub` 直接报错）。
- 一个文件 = 一个模块。`module("path.zx")` 是编译期内建，返回文件命名空间（相对**导入方文件**解析）。
- **模块之间不共享名字**：每个 `Module` 自己的 `Scope`，无父作用域。`ensure(sym)` 包一层
  `ensure_raw`，临时把 `g_scope`/`g_mod`/`g_srcpath` 切到符号所属模块再恢复；
  待检查的函数体带着自己的 `Module *` 排队。
- 非入口模块的顶层名字加 `stem_` 前缀（`util_add`），入口文件保持素名（`main`）。
  前缀在 `mangle_name()` 里做；`path_stem` 保留原始字符，所以报错里看到的是 `priv-util` 而不是 `priv_util`。
- 跨模块只认 `pub`，报错：
  `'secret' is private to module 'util'; mark it \`pub\` to export it`。
- **循环导入是硬错**（`loading` 标志，入口模块也置位）；模块不得声明 `main`；入口文件不可被导入。
- 后端仍是**单编译单元**：`backend_emit` 按 `sema_module_count()/sema_module_root(mi)` 遍历，
  非入口模块的名字全 `static`，`is_main` 只认 `mi == 0`。

### 后端：视图型全局不能物化

`var arr = &.{0,1,2}; const view = arr[0..]; arr.1 = 99;` —— 把 view 物化成静态数据
就**丢了别名**。加 `is_view_expr()`（只认 `NK_SLICE/NK_UN/NK_CAST/NK_IDENT/NK_FIELD`），
这类全局声明成 `static T x = {0};`，在生成的 `zx_init_globals()` 里按源表达式赋值。

## M7：缺返回路径分析（到达性）

用户要求：「做缺返回路径分析」。核心认识：**这是到达性问题，不是类型问题**——
`fn f(n: i32) i32 { if (n > 0) { return 1; } }` 类型上挑不出毛病，但条件不成立就掉出末尾。

实现（`src/sema.c`，放在 `check_switch` 之后、`check_fn_body` 里调 `check_return_paths`）：

- `falls_through(block)` / `stmt_ends(stmt)` / `arm_ends(arm)` 三个互递归函数。
- 能拦住路径的只有三样：`return`/`continue`、类型是 `TY_NORETURN` 的表达式（`@trap()`、
  noreturn 调用）、退不出来的循环（只有 `while (true)`）。
- `if` 用 `if_const()`（与 `check_if` 的 `known` 判定必须一致，否则死分支的
  半成品类型会误报）；`switch_ends()` 要求覆盖穷尽：枚举/联合体看 `Type.fields`，
  `?T`={some,none}、`!T`={ok,err}、bool={true,false}，整数永不认为穷尽。
- `main` 例外（掉出末尾 = `return 0`，后端本来就发）；`noreturn` 函数反而必须回不来。
- 泛型：`specialize()` 里是直接 `check_block(g->b)`，不经过 `check_fn_body` ——
  必须在那儿也调一次 `check_return_paths`，否则泛型的缺返回永远查不出来。
  重复报告用 `g_ret_diag[16][2]` 按 (line,col) 去重（两个实例只报一次）。

**逼出来的三个真 bug**：

1. `for (0..)` 单独出现时后端把"没有上界"当成"长度 0"，生成 `_i0 < 0`，循环一次都不跑。
   按 spec §8.3（`lo..` 只是跟着别的序列走的下标），sema 现在直接报
   `.. without an upper bound needs another sequence to take the length from`；
   后端也补了 `infinite` 分支当保险。
2. `@trap()` 在检查阶段折叠时报 "@trap reached at compile time"，任何函数里写一句
   就误报。改成只有 `g_ct_exec > 0`（编译期真的在执行）才算到达，并用 `n->flag`
   保证只报一次。
3. **parser**：`switch (b) { true: { … }, }` 被读成"给块加标签 true"——因为
   `parse_primary` 里 `IDENT ':'` 后面跟 `{` 就当标签块。加了 `is_bool_word()` 特判
   （`parse_primary` 的标签分支、switch 的臂标签分支、语句层的 `IDENT ':'` 三处）。
   bool 的表达式臂形式（`true: 1,`）以前能跑，其实是块标签的巧合，现在是真的模式。

测试：`tests/good/returns.zx`（11 个"每条路径都返回"的函数 + 运行输出）、
`tests/bad/{missing-return,missing-return-for,missing-return-switch,
missing-return-generic,noreturn-fallthrough,for-open-range}.zx`。
`sh test.sh` → **72 项全过**（语法 7 + 语义 17 + 反例 30 + 运行 17 + 多文件 1）。

文档：spec §9.1（每条路径都要返回 + 三样拦路条件 + main 例外）、§10 switch 穷尽性
改成"由 §9.1 间接要求"、decisions §21、README 加「缺返回路径（M7）」章节
和 parser 第三处消歧。README 待办里删掉这条，换成"不可达语句"和"独立 switch 穷尽性错误"。

## M8：不可达代码 + 运行时格式串 + `std.format(alloc, …)`

用户要求：「继续做,接下来性价比最高的是把"某条语句后一定到不了"接上，直接报不可达代码；
然后才是运行时格式串和 std.format(alloc, …)」。三件都做完了。

### 1. 不可达代码（sema.c）

`stmt_blocks_next()` = `stmt_ends()` 多认一个 `NK_YIELD`，其余复用缺返回分析的判定。
放在 `check_stmts()` 里：一旦 `dead`，后续每条语句报一次（按 (line,col) 去重）。

- **必须按位置去重，不能按指针**：编译期折叠会把函数体 `clone_tree` 一份再检查
  （`ct_call`），同一句有两个不同指针，第一版按指针去重报了两次。
- **标签块不能误判**：`out: { … }` 收完值继续往下走，而 `falls_through` 不认收割，
  所以 `stmt_ends(块)` 只在块里真的 return/continue 时为真——刚好保守正确。
- 报错带原因：`unreachable code: the `return` / `while (true)` / `switch` / `if`/`else`
  / `continue` / expression of type `noreturn` above never falls through`。

### 2. 运行时格式串（backend.c）

`fmt` 没有编译期值时不再报错，改生成 `zx_fmt_out(stdout, fmt, (ZxFmtArg[]){…}, n, nl)`。

- 实参统一进 `ZxFmtArg { kind, i, d, p, n }`，用 `zx_fa_i/u/f/b/s/c/p` 装——
  **每个实参只求值一次**（直接展开复合字面量会把切片求值两遍）。
- 分派顺序**照抄** `fmt_spec`：字符串 → {c} → bool → 浮点 → {b} → 整数 → 指针。
  `{d}` 套字符串仍打印字符串（两条路径行为一致 > 更严格）。
- 非 u8 切片按指针走（`zx_fa_p(&slice)`），否则 C 类型不匹配编译不过。
- **踩坑**：后端生成的函数体在 g_bbody（在所有用户函数之后），`zx_fa_*` /
  `zx_sink_put` / `zx_fmt` 必须先往 g_bproto 里补原型，否则 C99 报
  "call to undeclared function"。
- 格式串校验（占位符个数、{N} 越界）**从后端搬到 sema 的 `check_fmt_args`**：
  反例组只跑 `zxc file.zx`（不 `-o`），后端根本不执行，校验放后端永远测不到。

### 3. `std.format(alloc, fmt, args…) → ![]u8`

- 分配器是真类型：`Allocator { alloc: fn(usize) ?*u8, free: fn(*u8, usize) void }`，
  `sema_allocator_type()` 里用 `static Node id` 当身份（后端 `agg_name` 按 `t->decl`
  编号，decl 为 NULL 的类型会全撞成一个 C 名）。`base_type()` 里加了 `Allocator`
  这个名字，所以能写 `fn render(a: Allocator) ![]u8`。
- `std.heap.page` 是 `SK_CONST` 符号，`cname = "zx_alloc_page"`，`ct` 是两元素 V_AGG
  （只为过 R1）；C 里是 `static ZxS1 zx_alloc_page = { zx_page_alloc, zx_page_free };`，
  由 `ex()` 碰到这个名字时置 `g_need_page`，在 `emit_fmt_runtime()` 里补上。
- `ns_member` 加 `BI_HEAP`（`std.heap`）；`check_field` 的 `if (m->builtin)` 要放行
  BI_HEAP，否则 `std.heap` 被当成建函数返回值 `void`。
- `zx_format`：量长度 → `al.alloc(need)` → 再写一遍 → 末尾补 `\0`；失败返回 tag=1。
- 释放就是 `alloc.free(s.ptr, s.len)`——字段里存函数指针，调用走既有 NK_CALL 路径，
  不用为方法调用加任何东西。
- `emit_fmt_runtime()` 里有 `core = g_need_fmt || g_need_allocfmt`：只提到
  `std.heap.page` 时不带整个格式化器；页分配器的**函数体**必须跟着全局定义一起发
  （不能留在函数末尾的 `if (!core) return` 之后，否则只有声明没有定义）。

## M9：指针算术 + 指针↔整数 + 自引用类型（自建 arena 跑通）

用户要求：实现 `p + n` 和 `(usize)p` / `(*u8)i` 的代码生成，好让 `std.format` 能吃到
用户自己的分配器。

### sema（`check_ptr_arith` / `ptr_offset_type`）

- `p + n` / `n + p` / `p - n` → `*T`：**结果丢掉 `has_len`**（`*[N]T + 1` 是 `*T`，
  数量没法跟着减）。`p - q` → `usize`，要求 `ty_eq(a->elem, b->elem)`。
- 偏移量只收 `usize` + `comptime_int` 字面量（字面量就地定型成 usize）。
  `i32` 偏移报错并在信息里写解法：`write (usize)…`。
- `p + q` / `p * n` 报 `only \`+\` and \`-\` apply to pointers` / `cannot add two pointers`。
- `check_assign`：`lt->kind == TY_PTR` 且 `+=` / `-=` 走单独分支（否则
  `check_num_operands` 会说"arithmetic needs numbers"）。
- 编译期：`V_PTR ± int` 只挪 `off`（`p - q` 要求同一个 `base`），所以
  `const mid = nums[0..].ptr + 1; const v = mid.0;` 仍满足 R1。

### backend

- **关键坑**：`*[N]T` 在 C 里是 `T(*)[N]`，直接 `+1` 跳 N 个元素。所以生成
  `((T*)((Elem*)p + n))`，`p - q` 两边也先退成元素指针再减。
  `p += n` 同理，最后再 cast 回原类型。
- `coerce`：`ptr → int` / `int → ptr` 都过 `uintptr_t` 中转，避免 64 位截断警告。
- `is_view_expr` 认 `NK_BIN`（指针 ± ）：全局 `const mid = arr[0..].ptr + 1;`
  必须走 `zx_init_globals()`，不能物化。

### 顺带修的两个真 bug

1. **`?T` 的 tag 反了**：`zx_page_alloc` 写 `r.tag = (payload == 0)`（当失败标志），
   `zx_format` 里 `if (mem.tag)` 判失败；可语言里 `?T` 的 tag 是"**有值**"
   （`!T` 的 tag 才是错误码，0=ok）。内置分配器两头都反所以自洽，用户写的分配器
   一接上就永远"分配失败"。统一成语言语义：`r.tag = (payload != 0)`、`if (!mem.tag)`。
2. **自引用类型解析不出来**：`const Node = struct { next: ?*Node }` 报
   `cyclic dependency while resolving 'Node'`（R5 明明说合法）。做法：
   - `ensure_raw` 解析初始值之前先 `ty_agg(kind, decl, NULL)` 建外壳挂到符号，
     `state = 3`（"外壳就绪、成员表没填"）；
   - `resolve_type` 遇 `state == 3` 直接还外壳，不走 `ensure`；
   - `resolve_struct_body` 里 `ft == agg` → `field 'x' contains the struct by value`；
   - `ty_size`/`ty_align` 加 `-2` 哨兵（正在算）防爆栈；
   - C 里前向声明 `typedef struct ZxS1 ZxS1;` 必须写在**字段处理之前**（否则
     `?*Node` 的 typedef 先引用未声明的 `ZxS1`）；
   - `ensure_type(TY_PTR)` 要递归注册元素类型。
