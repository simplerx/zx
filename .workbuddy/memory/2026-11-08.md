## zxc add <库目录>：目录树模式，不复制文件（05:30）
- 用户质疑上一轮设计：「通常头文件和源文件都会分开，还可能分多层路径，这样编译不是要自己动手复制文件吗？最怕库文件还不在一起，不知要复制哪些」。说得对——原 csrc.c 只扫 vendor/ 一层、要求 .h/.c 同目录同名，把整理文件的成本又推回用户，和「不费心力」矛盾。
- 方案：**`zxc add <库目录>` 指向库原本的目录树**（可工程外、相对/绝对路径都行），递归发现后写一张纯文本清单 `vendor/<名>.clib`（root/include/header/source/define 行）。清单是**编译输入**、可编辑（注释掉 source 行即裁剪），库文件一个都不复制。之后 add/build/run/test/cbuild 全按清单走。清单是静态快照，新增文件跑 `zxc add <目录> --force` 刷新或手工加行。
- 新增 src/clib.c/.h：递归发现（跳过 tests/examples/build/docs/.git + 异平台目录；所有含 .h 的目录与 include/inc/public/src 都进 -I）、清单读写、伞头生成、按清单把**所有 .c 合成一个 lib<名>.a**（真实库多个 .c 互相引用，分组会缺符号）、.o 按路径哈希命名（多层同名 .c 不撞）、内容指纹增量（cc+flags+清单+所有源/头）。纯头库 0 source 合法：clib_read_manifest 不报错、clib_build 返回 0 且不写 @link。
- cbind.c/.h 扩三个参数：`extra_incs`（多 -I/-D 串）、`macro_headers[]`（多头扫 #define，加 macro_seen 去重）、`regen_arg`（生成物注释里的重生成命令要用用户真正敲的参数，否则伞头名会写成错误命令）。
- main.c：`cmd_add_tree`（目录分支由 path_is_dir 判定）、`--name`、重复 root 清单提醒、build_program 扫 vendor/*.clib 自动重编 + zx_add_link_lib 注入 + csrc_relink 强制重链、cbuild 支持清单名、usage/help、ZX_VERBOSE 补打 link cmd。
- **踩坑**：① 伞头把主头与它已 include 的子头都 include，子头没写 guard 就 `redefinition of 'Vec'`——守门用例抓到，改成 `header_includes` 去冗余，伞头只留「入口头」。② src/ 下内部头不该进对外绑定 → `is_public_header` 只认 include/inc/public/ 与 root 顶层头，内部头仍进 -I。③ 生成物注释写 `zxc add geolib.h` 是错的（伞头名）→ regen_arg。④ `--name` 再 add 会留两份清单、编两遍 → 检测同 root 并提示删旧。⑤ clib.c 的 walk() 跨平台分支曾重复定义 child 变量（Windows/POSIX 预处理拼接），改成两分支只算 name+isdir、公共段算路径。
- 非本次坑（记下避免再踩）：`zxc init .tmp/cadd/demo2` 会把整段路径写进 zx.json 的 name/out，导致 `-o "out/.tmp/cadd/demo2.exe"` 链接失败；要 `cd .tmp/cadd && zxc init demo2`。另外 Zx 字符串字面量是 `[]const u8`，C `const char*` 映射为 `*const u8`，调用要 `let s = "abc"; f(&s[0])`（既有语言边界，非本次功能）。
- 验证：工程外多层库 geolib（include/ + src/core/ + src/util/ + tests/ + examples/）端到端输出 `add=5 dot=13 v=5.5,2 counter=11 hash=96354 ver=3`；改深层 .c 后只跑 build 自动重编重链；清单注释行生效（.a 成员减少）；新增 .c 后 --force 刷新；--name / --no-build / 纯头库 / 单头模式 / 系统头配方 m,c 全不回归。test.sh 新增 2.54 两条守门；全量 272 passed / 0 failed、LSP 64 项全过。
- 行尾：main.c / docs/manual.md 仍纯 CRLF（全程二进制补丁）；新文件 clib.c/.h 与 cbind/csrc/test.sh/README.md/build.sh 是 LF。文档：README 调用 C 库章节首推目录模式，manual 新增 §3.19、§3.18 标注为「小库简写」。
