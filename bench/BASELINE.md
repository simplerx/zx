# Benchmark 基线

宿主侧计时（进程墙钟，含启动开销），每个程序跑 3 次取最好。
运行：`sh bench/run.sh`（或 `--quick` 跑一次）。

## 当前基线

- 日期：2026-11-02
- 编译器：bin/zxc.exe（M20），后端 zig cc `-std=c11 -O1`（`.toolchain/zig.exe cc`）
- 机器：Windows x86_64
- 分支：feature/union-enum（基线提交 93a284b 之后）

| 负载  | 耗时 (ms) | 校验和（正确性锚点，跨后端必须一致）          |

| fib   | 83        | fib(34)=5702887                               |
| mandel| 196       | sum=73280456                                  |
| mmat  | 149       | c00=6118 cN1=6191 cN2=6118 cNN=6187           |
| str   | 79        | len=108890 hash=2573974805                    |

## 负载说明

- **fib**：递归调用开销 + i64 算术（约 2,900 万次调用）
- **mandel**：1200×800 曼德博集合，f64 乘加内层循环 + 分支预测
- **mmat**：256×256 矩阵乘跑 3 遍，内存带宽 + 三重循环
- **str**：2 万次整数格式化 + 逐字节追加 ArrayList(u8)，分配器压力

## 以后怎么用

每次动后端 / 优化器之后跑一遍，和本表对比：

1. **校验和必须逐字符一致**——那是差分测试的锚点，C 后端、原生后端、
   未来的 LLVM 后端都要给出同样的输出；
2. 耗时显著回退（>5%）就是回归，先修再合。
