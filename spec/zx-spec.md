### 1.1 关键字（24 个）

```
const  let  var  fn  module  type  null  undefined
if  else  while  for  inline  switch  continue  return
defer  struct  union  enum  error  pub  extern  orelse
```

`pub` 只出现在文件作用域的声明前面，决定这个声明是否对外可见（§11）。

`module(...)` 是获取模块命名空间的唯一方式（§11）；把成员拿进当前作用域就是普通的 `const` 绑定。

`error` 是类型名（`error ≡ u16`）；`true` / `false` 是布尔字面量，不是关键字（技术上可被局部名遮蔽，不建议）。

注意**没有 `break`**：离开作用域靠收割语句 `tag: expr;`（§8.5），控制流关键字只剩 `continue` 和 `return`。

### 1.2 运算符

```
&  *  /  %  +  -  <<  >>  <  <=  >  >=  ==  !=  ~  !  |  ^  &&  ||
=  +=  -=  *=  /=  %=  &=  |=  ^=  <<=  >>=
.  .{  ..  ,  :  ;  (  )  [  ]  {  }  @
```

- `&` 二义：前缀是取地址，中缀是位与。由位置决定，无歧义。
- `*` 二义：前缀 / 类型位置是指针类型构造子，中缀是乘。**不再是取地址**。
- `!` 二义：前缀是逻辑非，类型位置是错误联合体。
- `.{` 是一个词法单元（`&.{…}` 与 `.{…}` 的开头），避免把 `.` + `{` 拆开解析。
- `{` 三义：作用域块 / 元组字面量 / 类型体，见 §4.1 的判定规则。
- `:` 的用途由位置区分：类型标注 `x: T`、结构体字段 `name: T`、联合体成员 `name: {tag, T}`、switch 臂 `模式: 体`、**标签与收割**。语句开头出现 `IDENT ":"` 只可能是标签作用域或收割语句（§8.5）。

## 3. 指针与数组

### 3.1 取地址与解引用

- **`&lvalue` → `*T`**（取地址）。合法操作数：变量、字段、下标、切片元素、`&.{…}` 字面量。
- **`.0` → 解引用**（元素 0）。指针、数组、元组统一用 `.下标`。
- **`.` 自动穿透一层指针**：`p.name` ≡ `p.0.name`。

```zx
var x: i32 = 1;
let p = &x;        // *i32
p.0 = 2;           // 解引用写入 → x == 2
let y = p.0;       // 2
```

没有独立的解引用运算符，也不需要 `->`。

`&letVar` 得到 `*const T`；把 `*T` 赋给 `*const T` 是免拷贝提升（R7），反过来不允许。

### 3.2 数组类型是 `*[N]T`

> **数组就是指针，但数量写在类型里。`*[N]T` 和 `*[4]T` 是两个不同的类型。**

```zx
*[3]i32      指向 3 个 i32 的起点，8 字节
*[4]i32      另一个类型，8 字节
*i32         指向"数量未知的 i32"，又是另一个类型
```

表示上三者完全一样（都只是一个地址），差别全在类型：

| 类型 | 大小 | `.len` | 元素个数检查 |
|---|---|---|---|
| `*[N]T` | 8 | `N`，编译期常量 | 有，`arr[3]` 在 N=3 时直接编译错误 |
| `*T` | 8 | 无（用了报错） | 无，只能靠约定 |
| `[]T` | 16 | 运行时值 | 运行时边界检查 |

所以"数组是指针"说的是**表示**：传参不复制、`@sizeOf(*[1000]i32) == 8`、`arr.0` 就是解引用。而"N 在类型里"说的是**类型**：它让编译器能区分长度，也让 `.len` 有地方来。

**互相转换**（R7 免拷贝提升 + 1 个显式转换）：

| 从 → 到 | 方式 | 理由 |
|---|---|---|
| `*[N]T` → `*T` | 隐式 | 丢数量，永远安全 |
| `*[N]T` → `[]T` | 隐式 | 数量变成运行时值 |
| `*T` → `*[N]T` | **显式** `(*[3]i32)p` | 断言"这里真有 3 个"，编译器无法验证 |
| `*[N]T` → `*[M]T`（N≠M） | **不允许** | 二者不同型，先退到 `*T` 再断言 |

```zx
var a = &.{1, 2, 3};            // *[3]i32
let p: *i32 = a;                // ✓ 隐式：丢数量
let s: []i32 = a;               // ✓ 隐式：数量进运行时
let q: *[3]i32 = (*[3]i32)p;    // ✓ 显式：把数量断回来
// let bad: *[4]i32 = a;        // ✗ *[3]i32 与 *[4]i32 不同型
```

`*[N]T` 里 N 可以是编译期表达式，泛型直接用它：

```zx
const Buffer = fn (T: type, n: usize) type {
    return struct { data: *[n]T, len: usize };   // n 进类型，不同 n 就是不同类型
};
```

### 3.3 `.len` 与 `.size`

两个编译器提供的只读字段：

| 字段 | 含义 | 类型 |
|---|---|---|
| `.len` | **元素个数** | `usize` |
| `.size` | **字节数**（`len × @sizeOf(T)`） | `usize` |

| 容器 | `.len` | `.size` |
|---|---|---|
| 数组 `*[N]T` | **N，编译期常量** | **N×sizeof(T)，编译期常量** |
| 指针 `*T` | 编译错误：改用 `*[N]T` 或 `[]T` | 同左 |
| 切片 `[]T` | 运行时 `usize` | 运行时 `len × @sizeOf(T)` |
| 元组 `{A,B,C}` | 字段数，编译期 | 总字节数，编译期 |

它们是**编译器字段**，不是内存里的成员：`&.{0,1,2}` 只占 8 字节，`.len` 在编译期就被换成常量 3。因此 `len` / `size` / `ptr` 三个名字**不能再作为结构体字段名**，声明时报错。

```zx
var array = &.{0, 1, 2};             // *[3]i32
let n = array.len;                   // 3，编译期常量，运行时没有读取动作
let bytes = array.size;              // 12，编译期
let bare: *i32 = array;              // 丢数量（R7.1），不需要 .ptr

let s: []i32 = array;                // 切片：16 字节 = 指针 + 运行时 len
let sp = s.ptr;                      // *i32，切片的真字段

let t = {1, 2.5, "hi"};
let tn = t.len;                      // 3
let tb = t.size;                     // 3 个字段的总字节数（含对齐填充）
```

数量只在 `*T` 上丢失，这正是"退化成裸指针"的代价：

```zx
fn head(p: *i32) i32 { p.len }            // 编译错误：*i32 没有数量
fn head2(p: *[3]i32) i32 { p.0 }          // 正确：数量在类型里
fn head3(xs: []const i32) i32 { xs.0 }    // 正确：切片带运行时长度
```

### 3.4 声明、读取、切片

```zx
var array = &.{0, 1, 2};            // *[3]i32，数量从字面量推出
var arr2: *[3]i32 = &.{0, 1, 2};    // 显式写出，与上面同型
var buf = std.stackAlloc(u8, 64);   // 栈帧上申请 64 字节，buf 是 *[64]u8

array.0          // 第一个元素（可写）
array.1          // 第二个元素
array[i]         // 运行时下标，带边界检查（N 已知，检查可优化掉）
array[0..]       // → []i32 切片，数量变成运行时值
array[1..3]      // → []i32
array.len        // 3，编译期
array.size       // 12，编译期
```

**跨函数传数组**三种写法，按"要不要长度"选：

```zx
fn sum(xs: []const i32) i32 { … }            // 长度随值走，16 字节，通用
fn sum3(xs: *const [3]i32) i32 { … }         // 长度在类型里，8 字节，只收 3 个的
fn sumAny(n: usize, xs: *const i32) i32 { … } // 长度另传，最灵活最丑
```

**空数组字面量**推不出元素类型，必须写期待类型：

```zx
let empty: *const [0]u8 = &.{};      // 唯一的合法写法
```

### 3.5 存储从哪来（规则 R9）

数组字面量 `&.{…}` 是一块**匿名存储**，编译器必须真的分配 `N × sizeof(T)` 字节。存储位置由"绑定形式 + 作用域"决定：

| 绑定形式 | 存储位置 | 绑定类型 | 透过它写 |
|---|---|---|---|
| `var a = &.{…};`（局部） | 当前栈帧 | `*[N]T` | 可以 |
| `let a = &.{…};`（局部） | 当前栈帧，初始化后只读 | `*const [N]T` | 不可以 |
| `const a = &.{…};` | 编译期物化的静态数据 | `*const [N]T` | 不可以 |
| 模块顶层的 `let` / `var` | 静态数据段 | 同上 | 同上 |
| `var x = std.stackAlloc(T, N);` | 当前栈帧 | `*[N]T` | 可以 |
| `var x = std.heapAlloc(a, T, N);` | 分配器给的 | `*[N]T` | 可以 |

`undefined` 在指针上**不再分配存储**（v0.10 起）：`var x: *[N]T = undefined;` 只是
"这个指针槽不初始化"，读它之前必须先指向某块真的存储。要内存就显式申请——分配点是
源码里可搜索的一行，读代码的人不用猜"这条声明背后藏了多大的空间"。模块顶层的
`var x: *[N]T = undefined` 仍落在静态数据段（顶层没有栈帧，历史行为保留）。

统一分配 API（两者都返回数组指针 `*[N]T`，`.len` 是编译期常量）：

- `std.stackAlloc(T, N)` —— 在当前栈帧上申请 N×sizeof(T) 字节。N 必须编译期已知
  （结果类型里带着长度）；存储活到**函数返回**，循环里每轮拿到的都是新的一块。
- `std.heapAlloc(alloc, T, N)` —— 穿过分配器的 `alloc` 去要。分配器显式传
  （§13 的约定）；没有可选可返回，OOM 直接 `abort`——要"可能失败"的分配，
  自己调 `alloc.alloc(bytes)` 走 `?*u8` 那条路。

**逃逸检查**：指向当前栈帧的指针不允许 `return` 出去——局部变量的槽位、`&.{…}`
的匿名存储、`std.stackAlloc` 的结果，以及它们的字段 / 下标 / 指针运算，返回时一律
报错；想活得比调用久，用 `std.heapAlloc`。经局部变量中转也逃不掉
（`var p = std.stackAlloc(...); return p;` 同样被拦）。已知保守面：栈指针存进
聚合体字段再整体取出来，追不到——宁漏勿误报。

写 `let` / `const` 时那块存储是只读的，所以类型必须是 `*const T`：

```zx
const nums: *const [3]i32 = &.{1, 2, 3};   // 正确
const bad:  *[3]i32 = &.{1, 2, 3};         // 编译错误：只读存储不能有可变指针
```

### 3.6 指针算术与指针 ↔ 整数

偏移量按**元素**算，不是按字节——和 C 的 `p + n` 一致：

| 表达式 | 结果 | 说明 |
|---|---|---|
| `p + n` / `n + p` | `*T` | 前进 n 个元素 |
| `p - n` | `*T` | 后退 n 个元素 |
| `p - q` | `usize` | 两个同型指针之间隔几个元素 |
| `p += n` / `p -= n` | — | 原地移动 |

结果类型总是 `*T`：**`*[N]T` 加一次就丢掉数量**（`arr + 1` 是 `*T`，不是 `*[N-1]T`）——数量没法在类型系统里跟着减。

`n` 必须是 `usize`，字面量例外（直接定型成 `usize`）。别的不做隐式转换（R4），错误信息直接给出写法：

```zx
let i: i32 = 2;
let bad = p + i;         // ✗ pointer arithmetic needs a `usize` offset, found `i32`; write `(usize)…`
let ok  = p + (usize)i;  // ✓
```

`p + q`、`p * 2`、`p < q` 都不允许；`p == q` / `p != q` 允许（比地址）。

指针 ↔ 整数的**显式**转换是自由的（R4），语义同 C：

```zx
let addr = (usize)buf[0..].ptr;    // 地址当数字
let p = (*u8)(addr + 3);           // 数字当地址
```

> 注意尺度：`*u8` 上的 `+n` 是 n 个字节，`*i32` 上的 `+n` 是 n×4 字节。要按字节移动，先转 `*u8`。

指针算术的结果**仍然是视图**：编译期能算出来的（编译期数组上的 `p + 1`、`p - q`）照样折叠，所以 `const` 里也可以用。

## 4. 元组、结构体、枚举、联合体

### 4.1 元组：`{…}`

类型 `{T1, T2, …}`，字面量 `{e1, e2, …}`，值类型（内联，不是指针）。

```zx
let t = {1, 2.5, "hi"};      // {comptime_int, comptime_float, []const u8}
t.0                          // 1
t.2                          // "hi"
t.len                        // 3，编译期
t.size                       // 总字节数，编译期
let {a, b, c} = t;           // 解构
```

**`{x}` 是一元组，不是块。** 这一条决定了整个块值规则：

| 写法 | 顶层内容 | 身份 | 值 |
|---|---|---|---|
| `{1, 2}` | 无 `;`、无声明 | 二元组 | `{i32, i32}` |
| `{x}` | 无 `;`、无声明 | **一元组** | `{T}` |
| `{x,}` | 同上（尾逗号允许） | 一元组，与 `{x}` 完全相同 | `{T}` |
| `{}` | 空 | 零元组 = `void` | `{}` |
| `{ f(); }` | 有 `;` | 块 | `{}` |
| `{ x = 0; }` | 有 `;` | 块 | `{}` |
| `{ let a = 1; a }` | 有声明 | 块 | `{}` |
| `{ 1 }` | 无 `;` | 一元组，**不是块** | `{comptime_int}` |

**块的值默认 `{}`；只有带标签的块能交出值，靠收割语句 `tag: expr;`。** 想用块算出一个值：

```zx
let a = one: { one: 1; };      // 1
let b = { 1; };                // {} —— 无标签，末尾表达式是语句，被丢弃
let c = { 1 };                 // 一元组 {i32}，不是块
```

这是 §4.1 那条规则的必然结果：`{x}` 既然必须是元组，块就不能再"自动继承末尾表达式的值"——否则 `{x}` 一定得是块（它有值 x）。两条规则只能留一条，留下的是"**块值只来自收割**"。好处是两件事都**完全由语法决定**：花括号的身份看顶层有没有 `;`，块有没有值看有没有标签——语义分析里不需要任何猜测。

代价很实在：**函数体、无标签的 `if` 分支都没有"最后一个表达式就是返回值"的写法了**——函数用 `return`，块用收割（§8.5），`if` 想有值就给臂加标签或用表达式臂的糖（§8.1）。

#### 花括号的判定规则

> 从 `{` 扫到匹配的 `}`，**只看顶层**（跳过嵌套括号）：
> - 出现 `;` 或 `const` / `let` / `var` / `fn` 声明 → **块**
> - 否则 → **聚合字面量（元组）**

```zx
{ 1, 2 }                      // 元组
{ let a = 1; a + 1 }          // 块，值 {}（a + 1 是语句）
{ f(); g() }                  // 块
{ x }                         // 一元组
{ x, }                        // 一元组（尾逗号）
{}                            // 空元组 = void
```

这条规则只在**解析局部**做一次前向扫描，不影响复杂度（每个花括号只扫自己的体，整体线性）。想跳过这次判断时写 `.{…}`——`.{` 是词法单元，直接告诉 parser"这是字面量"。

**强制块位置不看这条规则**：函数体，`if` / `while` / `for` 的体，`else` 体，`struct` / `union` / `enum` / `switch` 的体，`{` 一律是块。所以那里的 `{1, 2}` 是块（值 `{}`），不是元组——要交出元组，加标签后收割：`tag: {1, 2};`。

元组与数组在**读取**上是同一套语法，差别只在存储形态：

| | 元组 `{…}` | 数组 `&.{…}` |
|---|---|---|
| 类型 | `{i32, f32}`，值内联 | `*[N]T`，8 字节指针 |
| 元素类型 | 可以不同 | 必须相同 |
| `.N` | 只能编译期下标 | 编译期 `.0` 或运行时 `[i]` |
| 切片 `[a..b]` | 无（元素不连续同构） | → `[]T`，可传可迭代 |
| `for` | 不行（元组不是序列） | 不行（先 `arr[0..]` 变成切片） |
| 传参 | 按值复制整个元组 | 只传地址 |

### 4.2 结构体

```zx
const Person = struct {
    name: []const u8,
    age: i32 = 0,
};
```

- 结构体体是作用域，可放 `var` / `let` / `const` / `fn` / 嵌套类型（体里的 `fn` 是方法，见 §4.5）：

```zx
const V = struct {
    var i: i32 = 10;         // 静态字段：全程序一份
    const LIMIT = 100;
};
V.i = 20;
```

- 构造用 `.字段 = 值`：

```zx
var p = Person{ .name = "ann", .age = 30 };
p.age = 31;
let anon = { .x = 1, .y = 2 };     // 匿名结构体（.{ … } 同义）
```

- **有期望类型时，匿名字面量 `.{ … }` 就是那个类型**（R6）：字段按目标类型的字段类型检查，不必把类型名再写一遍。

```zx
var p: Person = .{ .name = "ann" };
fn zero() Person { return .{ .name = "" }; }
take(.{ .name = "bob" });
```

没有期望类型时它才自成一个匿名结构体（字段类型由初值推，`let anon = .{ .x = 1 };`）。

- 布局：声明顺序 + 自然对齐（C 兼容）。`struct(packed)` 紧凑无填充。

- **自引用必须经过指针**（R5）：`next: *Node` 合法，`next: Node` 是错误——值类型里放自己，大小无穷。

```zx
const Node = struct { value: i32, next: ?*Node };   // ✓
const Bad  = struct { value: i32, next: Bad };      // ✗ contains the struct by value
```

### 4.3 枚举：就是整数

```zx
const Color = enum { red, green = 5, blue };   // 底层 u32
const Small = enum(u8) { a, b };
```

- 变体就是整数：`Color.red == 0`、`Color.blue == 6`。
- 枚举体是作用域，可放 `fn` / `const`（见下）。
- 显式互转：`(u32)Color.red`、`(Color)5`。

**变体之外的成员**。变体表只有一个用途：给穷尽性检查、`{any}` 的变体名、C 那边的枚举常量用。所以成员的 `const` / `var` 不放变体表，另存一张常量表：

```zx
const Color = enum {
    red, green, blue,

    const FIRST = Color.red;          // 编译期常量，可用变体算
    var calls: u32 = 0;               // 挂在类型上的全局，整个程序一份

    fn name(self: Self) []const u8 {  // 方法：第一参数叫 self
        return switch (self) { Color.red => "red", Color.green => "green", Color.blue => "blue" };
    }
    fn isCool(self: Self) bool { return self != Color.red; }
    fn count() u32 { return 3; }      // 关联函数：第一参数不叫 self
    fn touch() void { Color.calls = Color.calls + 1; }
};

const s = Color.red.name();           // "red"
const n = Color.count();              // 3，可编译期求值
```

- 成员名不能与变体重名，也不能与别的方法重名。
- 关联函数（`Color.count()`）**没有接收者**，不能写成 `Color.red.count()`。
- 枚举的方法表与学生 struct 的方法表是同一套（§4.5）。

### 4.4 联合体（Zig 风格）

**首选写法：`union(enum)`**（v0.18）。变体名就是隐式枚举的成员，标签值按
声明顺序取 `0..n-1`；载荷类型直接写在冒号后面，不需要手写标签元组：

```zx
const Shape = union(enum) {
    circle: f64,
    rect:   { f64, f64 },          // 载荷本身是元组也可以
};

let s = Shape{ .circle = 2.0 };
switch (s.tag) {
    .circle: …,
    .rect:   …,
}
```

`union(enum(u8))` 指定标签的底层类型（默认 `u32`）；变体值仍按声明顺序
`0..n-1`，不可自定义。`s.tag` 的类型就是这个隐式枚举，穷尽性检查照常生效。

**显式标签形式**（成员是 `{标签值, 载荷类型}` 元组）：标签值可以是任何
编译期枚举变体或整数，需要跨类型共享标签或自定义数值时用它。

```zx
const ShapeTag = enum { circle, rect };

const Shape = union {
    circle: {ShapeTag.circle, f64},
    rect:   {ShapeTag.rect,   {f64, f64}},
};
```

**布局（v0.18 改定）**：带标签联合体一律**载荷在前、标签在后**——和
`?T` 的 `{值, ok}` 同一个方向（§5）。两种写法（糖 / 显式）物理布局一致。

**构造只写成员名，标签由编译器填**：

```zx
let s = Shape{ .circle = 2.0 };      // 标签自动 = ShapeTag.circle
let r = Shape{ .rect = {3.0, 4.0} }; // 载荷是元组 {f64, f64}
```

（也可以写全 `Shape{ .circle = {ShapeTag.circle, 2.0} }`，没人会这么写。）

**分派用 `switch`**（没有 `|x|` 载荷捕获——载荷直接用 `s.成员` 访问，与 `if` 捕获省略竖线的思路一致）：

```zx
let area = switch (s.tag) {
    .circle: 3.14159 * s.circle * s.circle,
    .rect:   s.rect.0 * s.rect.1,
};
```

- 对带标签联合体做**穷尽性检查**：漏掉成员又没 `else` 是编译错误。
- 臂体是表达式（值即臂值）或块（无值，除非加标签收割，见 §8.4）。
- 要修改载荷，取 `&s.circle`（`s` 必须是可变绑定）。

**读标签 / 读载荷的裸接口**（`switch` 不够用时）：

```zx
s.tag          // ShapeTag
s.circle       // 载荷；标签不匹配时是 UB
s.size         // 整个联合体占用的字节数
```

**普通联合体**（不带标签，读错成员 = UB）：

```zx
const Raw = union { i: i32, f: f32 };
let v = Raw{ .i = 42 };
v.f            // UB
```

`?T` / `!T` 也是带标签联合体（标签分别是 `bool` 和 `error`），但**首选写法是 `if` 捕获**，见 §8.1。

### 4.5 方法

结构体体、联合体体里的 `fn` 就是方法——**它是"第一个参数是接收者的普通函数"，没有别的**：

```zx
const Vec = struct {
    x: i32,
    y: i32,

    fn add(self: Self, o: Self) Self { return Self{ .x = self.x + o.x, .y = self.y + o.y }; }
    fn shift(self: *Self, d: i32) void { self.x = self.x + d; }
    fn len2(self: *const Self) i32 { return self.x * self.x + self.y * self.y; }
};

var a = Vec{ .x = 1, .y = 2 };
a.shift(10);      // ≡ Vec.shift(&a, 10)
a.add(a);         // ≡ Vec.add(a, a)
a.add(a).len2();  // 链式就是普通调用链
```

**两种写法完全等价**：`a.f(x)` 与 `Vec.f(a, x)`。所以「方法」不引入新的调用机制，只引入一点语法糖（把接收者补成第一个实参）和一条查表（`a.f` 这个名字先在字段里找，再到方法表里找）。

接收者三选一：

| 写法 | 含义 | 调用时要求 |
|---|---|---|
| `self: Self` | 按值拿到一份拷贝 | 什么都能传 |
| `self: *Self` | 改的就是调用者本身 | 接收者必须是可变绑定，且能取地址 |
| `self: *const Self` | 只读、不拷贝 | 能取地址即可，`const` 绑定也行 |

- `p.f()` 需要 `*Self` 而 `p` 是值时，编译器自动补 `&p`——所以 `a.shift(10)` 里的 `a` 必须是 `var`；对右值（`Vec{…}.shift(1)`）报错，先绑到 `let`。
- **`Self` 是体里的类型别名**，等于这个聚合体本身。自引用写 `next: ?*Self`，泛型体里也一样（见 §10.2）。
- **第一参数不叫 `self` 就是关联函数**：`fn count() u32` 写在体里，用 `Color.count()` / `Ints.init(al)` 调，没有接收者。代码生成上没有区别，区别只在怎么调——`x.f()` 找不到接收者可补。
- 方法**不能与字段重名**，参数里**不能出现 `type`**（泛型写在类型上，不写在方法上）。
- 联合体的方法照写，`self.tag` 读标签、`self.成员` 读载荷（§4.4）。

## 5. 空值与错误

```
error ≡ u16                              // 0 表示无错误
?T   ≡ union { some: {true, T}, none: {false} }
!T   ≡ union { ok:   {0,    T} }          // 其余 tag 是错误码
```

**物理布局：载荷在前，标签在尾部。**

```
?T   { payload: T     @0,  tag: bool  @sizeof(T) }
!T   { payload: T     @0,  tag: error @sizeof(T) }

align(?T) = align(T)
align(!T) = max(align(T), 2)          // tag 是 u16，必须落在 2 字节边界上
sizeof(?T) = align_up(sizeof(T) + 1, align(?T))
sizeof(!T) = align_up(sizeof(T) + 2, align(!T))

// 例：sizeof(?i32) = 8，sizeof(!i32) = 8，sizeof(!u8) = 4
// （若按 align(T) 直接算，!u8 会是 3 字节、tag 落在偏移 1，u16 未对齐）
```

为什么载荷在前：`&x`（`x: ?T` 或 `!T`）拿到的是 **payload 的地址**，于是 `*const ?T → *const T`、`*const !T → *const T` 是**零偏移重解释**，连 `T` 的对齐都不用知道。反过来若标签在前，payload 的偏移取决于 `align(T)`，`@ptrCast` 到 `*T` 会静默错位——正是要避免的那类错误。

| | 标签类型 | "有值" | "空 / 出错" |
|---|---|---|---|
| `?T` | `bool` | `tag == true` | `null`，即 `tag == false` |
| `!T` | `error`(u16) | `tag == 0` | 非 0 |

- `null` 就是布尔 `false`；`(bool)null == false`。
- `null` 是多态字面量：期望类型为 `?T` 时定型为该 `?T`。**它没有自己的类型**——
  离开"有 `?T` 落点"的位置（初始化、赋值、实参、返回、字段）就是编译错误：
  `let a = null;`、`null.?`、`null orelse x` 全错（§5.1）。
- `?T` / `!T` **不嵌套**（`??T`、`?!T` 是编译错误）。
- tag 为"空 / 出错"时 payload 是未初始化数据：**读它是 UB，取地址永远安全**。

```zx
let a: ?i32 = 5;
let b: ?i32 = null;
let c: !i32 = 5;              // tag 0
let d: !i32 = (error)1;

const p: *const i32 = &a;     // 与 &a.payload 同一地址，零偏移
const q: *const i32 = &c;     // 同上
```

对 `?T` / `!T` 取字段时，`.0` 是 payload，`.tag` 是标签。

### 5.1 取值：`orelse` 与 `.?`

三种退出方式，各有各的用途：`if` 捕获（§8.1）管"分支里做事"，`orelse` 管
"给个默认值"，`.?` 管"这里必须得有值"。

```
a orelse b        // 有值取 payload；空 / 出错取 b（b 只在需要时求值）
a.?               // 有值取 payload；空 / 出错 → 运行时 trap
```

| | 左值 | 结果类型 | 空 / 出错时 |
|---|---|---|---|
| `a orelse b` | `?T` / `!T` | `T` | 取 `b`（`b` 的类型必须是 `T`） |
| `a.?` | `?T` / `!T` | `T` | 打一行说明后 `abort()` |

- **`orelse` 是关键字，不是运算符**，优先级只比赋值高一层：`a orelse 0 + 1` 读作
  `a orelse (0 + 1)`，`a orelse b == c` 读作 `(a orelse b) == c`。它是"取个值回来"，
  不该比四则运算还黏。
- **`orelse` 右结合**：`a orelse b orelse 42` 是 `a orelse (b orelse 42)`，逐个往下退。
- **`b` 是惰性的**：左边有值就完全不求值——`x orelse expensive()` 在 `x` 有值时
  不会付那次调用。实现上左边先落进一个临时量，保证只求值一次。
- **`a.?` 是"我知道它有值"**：空 / 出错是程序 bug，不是可恢复错误。处置方式与整数
  除零一致（§7.R10）：`fflush(stdout)` → stderr 打 `zx: unwrap of a null optional at
  文件:行` → `abort()`。**不做 `try`/`catch` 那套**——Zx 没有异常，错误值就在返回值里，
  想处理就用 `if` 捕获或 `orelse`。
- **都不是左值**：`x.? = 1`、`(a orelse b) = 1` 是编译错误。要写就写进原变量。
- **`null` 不是 `?T`，只是给 `?T` 填空的字面量**：`.?` 和 `orelse` 的左值必须是
  真的 `?T` / `!T`，所以 `null.?`、`null orelse x` 是编译错误（E0301）——不是
  "运行时空解包"，是根本没东西可解。想表达"没有就用默认值"，先给那个"没有"
  一个名字：`const NONE: ?i32 = null;` 再 `NONE orelse 42`。
- **编译期能定就定**：`const NONE: ?i32 = null; const F: i32 = NONE orelse 42;`
  折成 `42`；`const N: i32 = SomeConst orelse 0;` 也折得出来。反过来，**编译期就
  看得出来是空**的可选值再 `.?` 直接报错（E0506）——它必然 abort，按 R10 的
  "能定就编译期定"不该留到运行期。`var z: ?i32 = null;` 之后的 `z.?` 不受影响
  （`z` 可以被赋值，那是运行期的事）。

```zx
const Node = struct { v: i32, next: ?*Node };

fn second(n: ?*Node) i32 {
    let p = n.?;                 // 这里必须真有节点
    return p.next.?.v;           // 第二层也一样
}

fn port(cfg: Config) u16 {
    return cfg.port orelse 8080; // 没配就用默认值
}

fn name(user: *User) []const u8 {
    return user.name.?;          // 这里必须有，缺了就该炸
}
```

## 6. 变量：三种绑定

| 形式 | 求值时机 | 存储 | 可写 | 取地址得到 |
|---|---|---|---|---|
| `const X = e;` | **必须编译期** | 无运行时存储（折叠 / 静态数据） | 否 | `*const T` |
| `let X: T = e;` | 运行时 | 栈 / 字段 | 否 | `*const T` |
| `var X: T = e;` | 运行时 | 栈 / 静态 / 字段 | 是 | `*T` |

`const` 管编译期（类型、函数、模块、常量表、泛型），`let` 管运行时只读，`var` 管可变。这是本版新增的关键划分：它让"读代码分得清什么是状态"这件事重新成立，同时 `const` 的语义保持 `plan` 原样。

```zx
const MAX = 100;                 // 编译期
let n: usize = compute();        // 运行时只读
var i: usize = 0;                // 可变
```

`var` 无类型标注时：整数字面量默认 `i32`，浮点 `f64`，其余按初值类型。

### R1 编译期规则

> **凡 `const`，编译器必须能在编译期算出值**，否则报错。

编译期可以调用 `const` 函数、跑 `if`/`while`/`for`/`switch`、构造聚合值、使用 `type`。

```zx
const add = fn (a: i32, b: i32) i32 { a + b };
const four = add(2, 2);          // 折叠为 4，运行时零开销
```

"能在编译期算出值"的边界（v0.6 起由编译器强制检查）：

- **读 `var` / 参数 / 捕获**只有发生在编译期真的在跑的时候（`const f = fn(…){…}`
  的函数体、被折叠的块/循环）才拿得到值。普通表达式里读它们就是"没有编译期值"，
  所以 `const k = runtimeVar + 1` 报错，而不是悄悄折叠成一个过时的数。
- **切片与指针是视图**，不复制数据：`s[1..3]`、`arr[0..]`、`&x`、`s.len`、`s.size`、
  `s[0]`、切片的 `.ptr` 全部能在编译期算出值（只是挪起点、改长度）。
- 算不出来的就报错，不会退化成"运行时初始化"。

编译期算出来的指针和聚合值会**物化为静态数据**，因此允许指向编译期局部量的指针逃逸出块：

```zx
const table = build: {
    var t = &.{0, 0, 0, 0};
    var i: usize = 0;
    while (i < 4) { t[i] = (u8)i; i = i + 1; }
    build: t;                    // 收割：块的值靠它交出
};
```

### R2 参数与捕获：只读运行时槽位

函数参数、`if`/`while`/`switch` 的捕获名，都是**只读运行时槽位**，不写 `const`/`let`/`var`：

- 只读，函数体内不可赋值（要可变写 `var a: T`）
- 是 comptime 还是 runtime，**由调用点决定**：实参全是编译期值 → 整个调用编译期完成；否则是运行时槽位
- 捕获是**值拷贝**；`&v` 得到指向该槽位的 `*const T`，不会影响原对象

### R3 作用域即值（值只来自收割）

每个 `{}` 都是作用域；作为表达式时它的值默认 `{}`，**只有带标签的作用域能通过收割语句交出值**：

```zx
let a = one: { one: 1; };        // 1
let b = { 1; };                  // {}（无标签；末尾表达式是语句，不产生值）
let c = { 1 };                   // 一元组 {i32}，不是块
```

- 收割语句 `tag: expr;` 给标签为 `tag` 的作用域设值，并**立即离开**它——跳出和带值是同一条语句（§8.5）。
- 同一作用域里可以有多个收割点，所有值的类型必须统一（R6）。
- 没执行过收割的标签作用域，值是 `{}`；无标签的块永远是 `{}`。
- `if` / `while` / `for` / `switch` 都是块，所以都是表达式。
- 函数体不参与收割：返回值只能靠 `return`（§9）。

收割可以穿过中间的无标签结构（`if` 块臂、循环体等）直接命中目标标签作用域——在深层嵌套里想结束外层循环，收割语句写在哪一层都行。

## 7. 表达式与运算符

优先级从低到高：

```
=  +=  -=  *=  /=  %=  &=  |=  ^=  <<=  >>=    右结合
orelse                                        右结合（关键字形式，不是运算符）
||
&&
==  !=
<  <=  >  >=
|
^
&
<<  >>
+  -
*  /  %
前缀： &  -  !  ~  (T)                          右结合
后缀： .name  .N  .len  .size  .?  [i]  [a..b]  (args)
```

- `&x` 取地址；中缀 `&` 是位与。
- 位运算只对整数；`&& ||` 只对 `bool`，短路。
- 没有自增自减，没有三元 `?:`（用 `if (c) a else b`）。

### R4 只有显式转换

`(T)e` 是 C 风格强制转换，前缀，右结合。

```zx
let a: i32 = 300;
let b = (u8)a;      // 截断为 44
```

| 目标 \ 来源 | 窄→宽 | 宽→窄 | int↔float | float→int |
|---|---|---|---|---|
| 整数 | 零/符号扩展 | 截断（保留低位） | 舍入 | 向零截断 |
| 浮点 | 精确 | 舍入 | — | — |

指针 ↔ 整数、指针 ↔ 指针一律允许，语义同 C。**没有任何隐式数值转换**：`i32 + i64` 是编译错误。

### R5 名字解析

同一作用域（含模块顶层）的声明**互相可见，与书写顺序无关**；求值是惰性的、按依赖拓扑排序，成环报错。互递归函数、自引用类型（`struct { next: *Node }`）因此天然合法。

### R6 期望类型驱动

`return`、赋值、`if` / `switch` 的臂（表达式臂和收割值）、结构体字段、函数实参都按目标类型解释来源表达式，让 R7 的提升有机会发生：

```zx
const f = fn (n: usize) !usize {
    return if (n == 0) (error)1 else n;    // 两个臂统一为 !usize
};
```

### R7 免拷贝提升（唯一的"隐式"，不是转换）

1. `*[N]T` → `*T`（丢数量，永远安全）
2. `*[N]T` → `[]T`（数量变成常量 len）；可同时加 `const`
3. `*T` → `*const T`（加只读，反向不允许）
4. `T` → `?T`、`T` → `!T`（补标签）
5. `comptime_int` / `comptime_float` → 宽度足够的具体数值类型

**没有期望类型时的默认**（`var x = e;` 这种）：整数字面量 → `i32`，浮点 → `f64`，数组字面量 `&.{…}` 的元素按同样规则定型（`&.{1,2}` 是 `*[2]i32`，`&.{1.0}` 是 `*[1]f64`）。

注意**反方向一律不是隐式的**：`*T` → `*[N]T` 必须写 `(*[N]T)p`，因为那是"我保证这里有 N 个"，编译器验证不了。

### R8 数量在类型里，但表示仍是地址

`*[N]T` 是**独立类型**：`*[3]i32` 与 `*[4]i32` 不同型，与 `*i32` 也不同型。但三者表示相同（8 字节地址），`@sizeOf` 都是 8，传参都不复制。

| 操作 | 允许？ |
|---|---|
| `*[3]i32` → `*i32` | ✓ 隐式（R7.1） |
| `*[3]i32` → `[]i32` | ✓ 隐式（R7.2） |
| `*i32` → `*[3]i32` | ✓ 但必须显式 `(*[3]i32)p` |
| `*[3]i32` → `*[4]i32` | ✗ 不同型。先退到 `*i32` 再断言，或本来就不该这么写 |

它的价值：
- `.len` / `.size` 有确定来源（就是 N），不依赖"声明处记不记得"
- 函数签名能表达"我只要 3 个"：`fn dot(a: *const [3]f32, b: *const [3]f32) f32`
- 泛型参数 `n` 直接进类型，不同 `n` 自动单态化成不同代码

### R10 数值语义（溢出、除零、移位、浮点）

**整数是按声明位宽回绕的（two's complement），不是未定义行为。**
`i8` 的 `127 + 1` 就是 `-128`，`u8` 的 `255 + 1` 就是 `0`，`i32` 的
`2147483647 + 1` 就是 `-2147483648`。`+ - * <<` 与 `+= -= *= <<=` 一律如此，
结果按**目标类型的位宽**截断——这一条由后端显式实现（先按无符号算再回转），
不依赖 C 的整数提升，因此 `-O0` 与 `-O3` 结果一致。

| 运算 | 语义 |
|---|---|
| `a + b` / `a - b` / `a * b` | 模 2^bits 回绕 |
| `a / b` / `a % b`（`b != 0`） | 向零截断的商 / 余数；`iN` 的 `MIN / -1` 回绕成 `MIN`，不 trap |
| `a / b` / `a % b`（`b == 0`） | 编译期可见 → 编译错误；运行时 → `zx: division by zero` 后 abort（不是 UB，不是静默 0） |
| `a << n` / `a >> n` | `n` 先按位宽掩码（`n & (bits-1)`）；右移有符号数按符号位填（算术右移） |
| `~a` / `-a` / 位运算 | 按位宽，无 UB |
| `a & b`、`a \| b`、`a ^ b` | 按位宽 |

**浮点是 IEEE-754**（`f16` / `f32` / `f64`）：除零得 `±inf` 而不是错误，
`0.0/0.0` 得 `nan`，比较遵守 IEEE（NaN 不等于任何值，包括自己）。
浮点 → 整数的转换超出目标范围时**目前是未定义的**（与 C 一致，已知缺口，
留待后续版本定义；正常的截断是向零）。

**字面量必须装进目标类型。** `let a: i8 = 300;`、`let b: u8 = -1;`、
`let c: i128 = <i128 最大值 + 1>;` 都是编译错误，不会静默截断。
唯一例外是类型的**最小值**：`-170141183460469231731687303715884105728`
（i128 最小值）里的正数字面量是 max+1，出现在一元 `-` 下时放行。

**编译期运算与运行时同宽、同为回绕。** 检查只针对"单个字面量"——表达式里的
运算按目标类型位宽进行，因此 `let x: i8 = 100 * 2;` 得到 `-56`（与运行时
`var a: i8 = 100; a * 2` 完全一致）。这条是为了让"编译期折叠"和"运行时"，
不可能给出两个答案；要抓溢出请用更宽的类型或显式检查。

**128 位是一等公民**：`i128` / `u128` 的字面量、算术、比较、`{}` 打印、
结构体字段全部可用，`{}` 打印走十进制全精度字符串（不是 64 位截断）。

## 8. 控制流

### 8.1 if

```
if (cond)      { … }                     // 块臂：语句体，无值（块默认 {}）
if (cond)      e1 else e2                // 表达式臂：糖，值即 if 的值
if (cond)      t1: { …; t1: a; } else t2: { …; t2: b; }   // 标签块臂
if (cond)      { … } else { … }
if (u) v       { … }                     // 捕获 ?T / !T 的载荷
if (u) v       { … } else e { … }        // 失败分支也捕获
if (u) v       e1 else e2                // 捕获 + 单个返回值
```

- `cond` 必须是 `bool`。
- `u` 是 `?T` / `!T` 时**直接写捕获名 `v`，不写 `|v|`**。
- `v` 是载荷的值拷贝，只读；`&v` 得 `*const T`。
- `else e`：`?T` 时 `e` 是 `null`（`bool`），`!T` 时 `e` 是错误码。
- **单语句臂（v0.13/v0.15）**：臂里只有一条语句时，花括号可以省掉。
  解析时就是包一层单语句块，语义与写块完全一致。
  - `return` / `continue` / `defer`（v0.13）：`if (c) return x;`、`if (o) v return v;`
  - **一条表达式语句**（v0.15）：`if (c) call(); else other();`、
    `if (c) x = 1; else x = 2;`、`if (n) v use(v); else report();`。
    这里的**分号属于臂**，不是外层语句的结束符——判据是分号后面紧跟 `else`。
    只写 `if (c) call();`（没有 else）时，分号照旧归外层语句，两种读法结果相同。
  - 其余语句仍要写块（多条语句、嵌套控制流）：`if (c) { a = 1; b = 2; }`、
    `if (c) { if (d) { … } }`。
  - 值形态不受影响：`let x = if (c) a else b;` 的臂后面跟的是 `else` 而不是分号，
    仍是表达式臂。
- **捕获名后面只能是块，或者单个返回值**。语句一律写进块里：
  `if (u) v { if (v > 0) { … } }`。
  像 `if (u) v if (v > 0) { … }` 这种写法在语法上无法区分"第二个 `if` 是分支体"
  和"第二个 `if` 是兄弟语句"——两种读法都能过，语义却完全不同（后者会先判断 `u`、
  丢掉结果，然后无条件判断 `v`）。与其猜，不如要求写块：这种写法直接报错。
- **表达式臂是糖**：`if (c) a else b` 的每个臂等价于一个匿名标签块里的收割。两个臂的类型必须统一（R6）。
- **标签块臂**：臂里的收割语句把值交给这个臂。臂的标签各自独立，名字不必相同。
- 也可以把标签加在 `if` 本身，两条臂共用一个标签，**推荐写法**。
- 无标签块臂是普通语句体，值为 `{}`。

```zx
// 语句形式
if (n) v { use(v); } else { std.print("null\n"); }

// 值形式一：表达式臂（糖）
let max = if (a > b) a else b;
let r = if (n) v * 2 else 0;         // 捕获 + 表达式臂

// 值形式二：标签加在 if 上（推荐）
let sign = s: if (x > 0) {
    s: 1;
} else if (x < 0) {
    s: -1;
} else {
    s: 0;
};
```

块臂里写收割语句照样生效，**收割可以穿过 if** 落到外面的标签作用域——在分支里收割的意图几乎总是"结束外层循环"：

```zx
done: for (xs[0..]) x {
    if (x == 0) { done: {}; }        // 收割目标是 for：结束循环，值 {}
    total = total + x;
}
```

### 8.2 while

```
while (cond)        { … }
while (u) v         { … }                  // 循环到空/出错
while (u) v         { … } else e { … }     // 结束时执行 else
while (cond)        { … } else { … }
```

- `u` 形式每轮重新求值 `u`，有值则绑定 `v` 执行体，为空/出错则结束并把终止值交给 `else`。
- 没有 `: (自增)` 子句，自增写在体内。

```zx
var i: usize = 0;
while (i < 10) { i = i + 1; }

while (it.next()) v { total = total + v; } else { std.print("done\n"); }
```

### 8.3 for

```
for (seq)              x       { … }
for (seq1, seq2)       x, y    { … }
for (xs, 0..)          x, i    { … }      // 值 + 下标，最常用
for (0..n, 0..m)       i, j    { … }
for (…) … { … } else { … }
```

- 序列**只有两种**：切片 `[]T`、整数范围 `lo..hi`（左闭右开，两端同型整数）。
- **序列个数 = 绑定个数**，一一对应；绑定名直接写，不带 `| |`。
- 所有序列**必须等长**：长度编译期能算出就编译期报错，否则安全模式下运行时断言。
- `lo..`（**省略上界**）只在多绑定时合法，上界取"其他序列的公共长度"——这是下标迭代的唯一写法，不引入"无限范围"的概念。
- 绑定是元素值的只读拷贝。
- 数组 `*[N]T` 不是序列，先 `arr[0..]` 变切片（零开销，只多存一个 N）。
- `else` 只在**正常跑完**时执行：`else 表达式` 是值形式（表达式的值就是循环的值），`else { … }` 是语句形式。收割离开时跳过 `else`。

```zx
for (xs) x { sum = sum + x; }                 // 单绑定
for (xs, 0..) x, i { buf[i] = x; }            // 值 + 下标
for (xs, ys) a, b { dot = dot + a * b; }      // 两个等长序列
for (0..n) i { buf[i] = 0; }                  // 纯整数范围
for (0..rows, 0..cols) r, c { grid[r][c] = 0; }
```

多绑定的等长检查：

```zx
const a: *const [3]i32 = &.{1, 2, 3};
const b: *const [4]i32 = &.{1, 2, 3, 4};
for (a[0..], b[0..]) x, y { … }     // 编译错误：3 ≠ 4
```

"长度编译期能算出"的三种情况：

| 序列 | 静态长度 | 说明 |
|---|---|---|
| `0..3` | 3 | 两端都是编译期整数 |
| `arr[0..]` | N | `arr` 是 `*[N]T`，长度写在类型里 |
| `&.{1,2,3}[0..]` | 3 | 数组字面量，元素个数就是长度 |
| `xs[1..3]` / `xs[0..]`（`xs` 是切片） | 不知道 | 切片只有 ptr + len，长度是运行时的 |
| `0..n`（`n` 是变量） | 不知道 | 同上 |

算得出来的必须相等，算不出来的交给运行时（安全模式下断言）。`for (a[0..2], b[0..2])`
对 `*[3]` 和 `*[2]` 是合法的——截出来的长度都是 2。

### 8.3.1 inline for：编译期展开

```
inline for (0..N)       i    { … }
inline for (0..len)          { … }        // 无绑定的纯重复
```

- `inline for` **不是循环**：语义层按序列的编译期长度把循环体克隆 N 份，每份把绑定
  换成对应的编译期常量。发出来的代码和手写 N 遍一模一样，运行时没有任何循环。
- 序列必须是**编译期长度**：`0..3`（两端都是编译期整数）、`@typeInfo(T).fieldCount`
  这类编译期值都行；运行时长度直接报错。
- 循环变量（绑定）是**编译期常量**：可以当数组长度用（`var buf: *[i + 1]u8`）、
  可以传给要求 `type` 或编译期字符串的内建。
- 每份展开是一个独立的块作用域：里面的 `let` / `var` 不会跨份撞名。
- **没有 `else`**（每份都执行，不存在"正常跑完"），也不带标签（收割没有意义——
  没有运行时循环可供跳出）。体里的 `continue` / `return` 照常作用于外层函数。
- 和泛型一样靠**克隆**实现：每一份都有自己的节点副本，编译期执行的中间值不会
  泄漏到别的份。

用途是配合 `@typeInfo`：`fieldCount` 有多少，`inline for` 就展开多少份，配合
`@fieldName` / `@fieldType` / `@field` 逐个字段访问——见 §14.1 的例子。

### 8.4 switch

```
switch (e) {
    模式              表达式,           // 表达式臂：值即臂值
    模式              { … },            // 块臂：语句体，无值
    模式        arm:  { …; arm: v; },   // 标签块臂：值来自收割
    模式         cap  { … },            // 捕获块臂（v0.20）：cap = 匹配到的东西
    else              表达式,
}
```

- 模式与臂体之间用 `:` 分隔；模式后可写**臂标签**（给块臂交值用）；臂与臂之间用 `,` 分隔。
- **捕获（v0.20）**：臂体前写一个名字、紧跟块，就是捕获——被捕获的是
  "匹配到的东西"：联合体臂捕获**变体载荷**（各臂类型不同），
  `?T` 的 `.some` 捕获载荷（`.none` 没有载荷，拒绝），`!T` 的 `.ok` 捕获载荷、
  `.err` 捕获错误值，枚举 / 整数 / bool 臂捕获**主语值本身**。捕获是只读绑定，
  作用域限于该臂；只允许单模式臂，`else` 臂没有东西可捕。捕获只配块臂——
  `cap 值` 和裸表达式臂没法区分，索性不允许。判别凭据是**名字后面紧跟 `{`**：
  `switch (s) { .circle: r { … } }` 是捕获，`.circle a: { …; a: v; }` 是臂标签
  （名字后面是 `:`）。
- 模式：`.成员`（枚举 / 联合体）、整数字面量（可逗号并列，如 `0, 1, 2`）、`else` 兜底。
- 对**整数 / 枚举**：按值匹配。
- **穷尽性是 switch 自己的规则**，与"这个 switch 有没有人要值"无关：
  枚举变体、带标签联合体的成员、`?T` 的 `some`/`none`、`!T` 的 `ok`/`err`、
  bool 的 `true`/`false` 必须列全（或有 `else`），否则
  `switch on `Color` is not exhaustive: missing `.blue``。
  整数 subject 永远不要求穷尽——2³² 个值列不完。
  （§9.1 的到达性检查复用同一条判据：switch 不穷尽 = 有一条掉出函数的路径。）
- 对**带标签联合体**：推荐直接 `switch (s)` + 捕获（v0.20）——
  `switch (s) { .circle: r { … } }` 的 `r` 就是载荷；也可以 `switch (s.tag)`
  按标签值匹配、载荷用 `s.成员` 访问。
- switch 是表达式：各臂产生的值必须统一（R6）——表达式臂的值、标签块臂的收割值。
- `?T` / `!T` 也能 `switch`（`.some` / `.ok` + `else`，`.err` 臂可捕获错误值）；
  简单解包首选 `if` 捕获。

```zx
let name = switch (color) {
    .red:   "red",
    .green: "green",
    else:   "other",
};

// 带标签联合体：块臂用收割交值
let area = switch (s.tag) {
    .circle a: {
        if (s.circle < 0) { a: (error)Err.negative; }
        a: 3.14159 * s.circle * s.circle;
    },
    .rect:  s.rect.0 * s.rect.1,       // 表达式臂直接给值
};
```

### 8.5 收割 / continue / 标签

**收割语句**是带值离开作用域的唯一方式（`break` 已删除）：

```
tag: expr;      // 给标签为 tag 的作用域设值 expr，并立即离开它
tag: {};        // 无值离开（值 {}）
```

- `tag` 匹配**最近一层**同名标签作用域；`expr` 先求值，然后该作用域的 `defer` 按 LIFO 执行，然后离开。
- 收割可以出现在目标作用域内的**任意嵌套深度**（`if` 块臂、循环体、另一个块里都行）——它穿过中间的无标签结构直接命中目标。
- 只有**带标签**的作用域能被收割。无标签的块既不能交值，也不能被提前离开——想提前离开，就给它加标签。
- 标签是独立命名空间（和变量、类型不冲突），同一函数内允许重名，内层遮蔽外层。

**哪些结构可以是标签作用域：**

| 写法 | 值 |
|---|---|
| `tag: { … }` 块 | 收割的值；没执行过收割就是 `{}` |
| `tag: for (…) x { … }` 循环 | 收割的值；正常跑完取 `else` 的值 |
| `tag: while (…) { … }` 循环 | 同上 |
| 函数体 | **不用标签**，用 `return` |
| `struct` / `union` / `enum` 的体 | 不能加标签 |

**跳出多层：给外层加标签。**

```zx
let hit = hit: for (0..rows) i {
    for (0..cols) j {
        if (grid[i][j] == 0) {
            hit: {i, j};              // 一次跳出两层，值是下标元组
        }
    }
} else null;
```

标签也能给普通块，用来"块算出一个值 + 提前退出"：

```zx
let area = shape: {
    if (w <= 0) { shape: 0; }
    shape: w * h;
};
```

**循环的 `else`**：只在正常跑完时执行，收割离开时跳过。`else 表达式` 是值形式，`else { … }` 是语句形式：

```zx
let firstBig = found: for (xs[0..]) x {
    if (x > 100) { found: x; }       // 收割：离开 for，值 = x
} else 0;                             // 正常跑完 → 值 = 0
```

`continue;` 跳过本轮剩余部分，进入下一轮；`continue :tag;` 直接进入外层标签循环的下一轮。

**语法判定**：语句位置遇到 `IDENT ":"`——后面跟 `for` / `while` / `switch` / `if` 是标签作用域；跟 `{` 时套用 §4.1 的花括号判定（元组 → 收割语句，块 → 标签作用域）；其他表达式是收割语句。规则只有一条：**`标签名: 值` 是收割，`标签名: 结构` 是打标签**。

### 8.6 defer：离开作用域时执行

```
defer expr;        // 语句形式
defer { … }        // 块形式
```

- 写在哪个块里，就在**那个块退出时**执行一次：正常结束、收割（`tag: expr;`）、`continue`、`return` 全都算。
- 同一个块里的多个 `defer` **逆序执行**（LIFO）：后声明的先跑。
- 表达式在**退出时求值**，不是 `defer` 那一行求值。所以 `defer free(buf)` 拿到的是 `buf` 的最终值。
- `defer` 是语句，不产生值，**不影响块的值**（块的值只来自收割，见 R3）。
- `defer` 体内不能收割 / `continue` / `return`（防止控制流跳进已退出作用域）。
- 条件执行用 `if (cond) { defer … }`，因为 `defer` 只认"所在块"。

```zx
const locked = fn (m: *Mutex, f: fn() void) void {
    m.lock();
    defer m.unlock();                    // 与 lock 成对，写在下一行
    f();
};
```

```zx
var x: i32 = 0;
{
    defer x = x + 100;                   // 块退出时才跑
    x = 1;
}                                        // 到这里 x == 101
```

**陷阱**：`return` 的表达式先算出来，`defer` 才跑。所以

```zx
const copy = fn (n: usize) []u8 {
    if (alloc.alloc(u8, n)) buf {
        defer alloc.free(buf);           // 任何路径退出都释放
        for (0..n) i { buf[i] = 0; }
        return buf;                      // ✗ 返回值指向已释放内存
    } else e {
        return &.{};                     // 长度 0
    }
};
```

是错的——`defer` 只适合"清理不影响返回值"的场景（锁、临时缓冲、计数器）。要"成功才不清理"，需要 `errdefer`（v0.2 候选）。

## 9. 函数

函数就是 `const` 指针。

```zx
const add = fn (a: i32, b: i32) i32 { return a + b; };

fn fact(n: i32) i32 {                  // 声明形式：允许自递归
    if (n <= 1) { return 1; }
    return n * fact(n - 1);
}
```

- **两种写法等价**：`fn name(…) R { … }` 就是 `const name = fn (…) R { … };` 的简写
  （都支持自递归）。规范形式是 const 绑定——函数是值。
- 类型 `fn(i32, i32) i32`，大小 8 字节。
- 没有 `->`，返回类型紧跟参数表。
- 无重载、无默认参数、无变参；多返回值用元组。
- `var a: T` 参数可写（强制运行时）；其余参数只读。
- `noreturn` 表示必不返回。
- **函数体是块，返回值只能靠 `return`。** 末尾表达式是语句，不是返回值：

```zx
fn bad() i32 { 1 }              // 编译错误：块值 {} 不是 i32
fn ok()  i32 { return 1; }      // ✓
```

函数体不参与标签收割；`return` 是离开函数的唯一方式。

### 9.1 每条路径都要返回（到达性检查）

返回类型不是 `void` / `noreturn` 时，函数体**每一条路径**都必须返回，编译器做
到达性分析：只要有一条路径能落到函数体末尾的 `}` 就是编译错误。

```zx
fn bad(n: i32) i32 {            // ✗ 条件不成立就掉出去了
    if (n > 0) { return 1; }
}

fn alsoBad(xs: []const i32) i32 {   // ✗ 循环可能一次都不跑
    for (xs) x { return x; }
}
```

能拦住路径的只有三样东西：

- `return` / `continue`；
- 类型是 `noreturn` 的表达式（`@trap()`、返回 `noreturn` 的函数调用）；
- 退不出来的循环：`while (true)`（`for` 的序列一定有限，所以 `for` 不算）。

`if` / `switch` 要**每条出路**都拦住才算拦住；`switch` 还要求覆盖穷尽——漏掉一个
枚举变体、`?T` 的 `.some`/`.none`、`!T` 的 `.ok`/`.err`、或 bool 的 `true`/`false`，
在运行时就是一条掉出函数的路径。

**`main` 是唯一的例外**：掉出末尾等价于 `return 0`（后端的隐式返回）。

### 9.2 不可达代码

同一条语句序列里，前面那条已经把控制转移走，后面的语句就**永远到不了**——这也是
编译错误，不是警告：

```zx
fn f(n: i32) i32 {
    return n;
    n + 1;              // ✗ unreachable code: the `return` above never falls through
}
```

判定和 §9.1 是同一条（能拦住路径的东西才能拦住后续语句），报错会点出原因：
`return` / `continue` / 收割 / `noreturn` 表达式 / `while (true)` / 每条出路都
离开的 `if` 或穷尽的 `switch`。

注意**标签块不算**：`out: { … }` 收完值仍然接着往下走，所以块后面不是死代码。

数组参数三种写法：

```zx
fn sumSlice(xs: []const i32) i32       // 长度随值走（推荐）
fn sumPtr(p: *const i32) i32           // 丢掉长度，只能靠约定
fn sumN(n: usize, p: *const [n]i32) i32 // 长度作为编译期参数
```

## 10. 泛型

`type` 是一等编译期值，泛型就是编译期函数，靠单态化实现。

```zx
// 可增长：长度是运行时值，所以用切片
const List = fn (T: type) type {
    return struct {
        data: []T,
        len: usize,
        cap: usize,
    };
};

// 定长：n 进类型，不同 n 是不同的类型，各自单态化
const Buffer = fn (T: type, n: usize) type {
    return struct {
        data: *[n]T,
        len: usize,
    };
};

const push = fn (T: type, l: *List(T), v: T) void {
    l.data[l.len] = v;
    l.len = l.len + 1;
};
```

`Buffer(u8, 4)` 和 `Buffer(u8, 8)` 是两个不同的类型，各自的 `data` 是 `*[4]u8` 和 `*[8]u8`——长度写错在编译期就报错，不会到运行时才越界。

- 可以带非类型参数，只要编译期可算。
- 不做 trait / 约束；需要约束时用编译期 `if` + `@typeInfo` 自检，报错在实例化点。
- 每次实例化生成独立代码。

### 10.1 实例名来自构造式

`Pair(i32)` 是一次编译期调用，结果**就是一个类型值**，可以随便起名字：

```zx
const Pair = fn (T: type) type { return struct { a: T, b: T }; };

const IPair = Pair(i32);          // 顶层别名
const P = Pair(i32);              // 同一个实例，同一个类型

std.println("{}", P{ .a = 1, .b = 2 });   // Pair(i32){a: 1, b: 2}
```

打印出来的名字**跟着构造式走，不跟着别名走**。同一个实例被几处 `const` 起名时，叫哪个名字取决于检查顺序——那是巧合，不是名字。值参数照样进名字：`List(i32, 2)`（不是 `List(i32, ?)`）。

类型标注里可以直接写实例：

```zx
var l: List(i32, 2) = List(i32, 2){ .buf = buf, .len = 0 };
```

### 10.2 泛型体里写 `Self`

体里不要再重复写自己：

```zx
const List = fn (T: type, cap: usize) type {
    return struct {
        buf: *[cap]T,
        len: usize,
        fn push(self: *Self, v: T) bool { … }   // ✓ T / cap 在方法体里照常可用
    };
};
```

写成 `fn push(self: *List(T, cap), …)` 会得到 `generic instantiation nests too deeply: 'List' asks for itself while it is still being defined`——定义还没结束就又要一份实例，永远收不了尾。

`T`、`cap` 这类编译期实参在方法体里是**编译期值**，C 那边没有对应的变量，用到的地方直接内联成字面量。

## 11. 模块

一个文件就是一个模块。

```zx
const std = module("std");
const math = module("lib/math.zx");
math.val = 10;                    // 写模块级 var
const Person = module("model.zx").Person;
```

1. 模块顶层只能有 `const` / `let` / `var` / `fn` 声明，没有自由语句。
2. `module(path)` 是编译期内建；同一路径返回同一实例。
3. 路径相对**调用者所在文件**；`"std"` 是内建模块。
4. 循环导入直接报错——模块之间不共享名字，也不需要拓扑排序。
5. **可见性由 `pub` 决定**：带 `pub` 的顶层声明对外可见，其余只在本文件内可见。
   模块名就是文件名（去掉 `.zx`），用于错误信息。

```zx
// util.zx
pub const VERSION: u32 = 3;
pub fn add(a: i32, b: i32) i32 { return a + b; }
fn secret(n: i32) i32 { return n * 2; }       // 私有

// main.zx
const util = module("util.zx");
const v = util.VERSION;                        // ok
const n = util.add(1, 2);                      // ok
// util.secret(1);                             // 错误：'secret' is private to module 'util'
```

6. `pub` 只允许出现在文件作用域；写在函数体里是错误。
7. 模块成员是**值**：`util.Point` 可以是类型，`util.add` 可以是函数，
   `util.VERSION` 是编译期常量——引用方式和普通名字完全一样。
8. 入口文件不允许被别的模块导入（那必然是循环）。

**把名字拿进来**：没有单独的导入语法。`const` 绑定一个模块成员就是别名——
函数、类型、命名空间、编译期常量一视同仁：

```zx
const math = module("lib/math.zx");
const square = math.square;        // 函数：以后直接 square(4)
const cube3  = math.cube;          // 顺便改名
const Vec2   = math.Vec2;          // 类型
const GOLDEN = math.GOLDEN;        // 编译期常量
const heap   = std.heap;           // 命名空间本身也能绑
```

- 别名只是**指向**：声明还是模块里那一份，函数体不会复制，`var` 还是同一个变量。
- 别名**不占存储**，不要求在编译期算出一个值（否则函数和类型根本绑不了）。
- 只能拿 `pub` 的名字；私有名字报错，名字不存在也报错，与本文件顶层声明重名同样报错。
- 绑定发生在文件作用域，顺序无关（R5）。

入口：

```zx
fn main() void
fn main() u8
fn main(args: []const []const u8) u8
```

### 11.1 格式化：能编译期就编译期

```zx
std.print(fmt, args…)         // 写 stdout，不换行
std.println(fmt, args…)       // 带换行
std.format(alloc, fmt, args…) // → ![]u8
std.io.print(h, fmt, args…)   // 写句柄 h，不换行（println 带换行）
```

1. **`fmt` 是编译期常量**（字符串字面量、`const` 串、由它们拼出来的串）→ 编译期解析成"逐段输出"的直接调用序列，运行时零解析、零分配。**这是默认路径，也是绝大多数情况。**
2. **`fmt` 是运行时值**（`[]const u8` 变量、外部输入）→ 回落到运行时解析器。语义与 1 完全相同，只是慢。
   `std.io.print` / `std.io.println` **一律走运行时解析器**（句柄要落成 `FILE*`，且只求值一次）；
   fmt 是编译期常量时动词与实参的校验照做，运行时只是又验一遍。
3. 两条路径共享同一份语法和类型规则。能静态判定的（占位符个数、下标越界）在编译期报错；判不了的（fmt 本身是变量）在运行时报同一个错误——`zx: format error: …` 之后中止。
4. 参数按值传入，不做隐式转换；要换宽度用显式转换（R4）。
5. `std.format` 一定要分配，所以**总是**走运行时写缓冲：先量一遍长度，再向分配器要内存，再写一遍，末尾补 `\0`（方便当 C 串用）。分配失败返回 `![]u8` 的 error 分支。
6. `alloc` 的类型是 `Allocator`：

```zx
const Allocator = struct {
    alloc: fn(usize) ?*u8,          // 要 n 字节，失败给 null
    free:  fn(*u8, usize) void,     // 还回去
};
```

   它是一个普通的结构体值，不是魔法；现成的只有 `std.heap.page`（向系统要页）。用完自己还：`alloc.free(s.ptr, s.len)`。

格式串：

```
{}       按顺序取下一个参数，默认格式
{0}      按索引取（可与 {} 混用）
{d}      十进制整数      {x} 十六进制      {b} 二进制
{s}      字符串          {c} 字符
{any}    结构展开（见 §11.2）：带类型名、带引号
{{  }}   字面量花括号
```

动词和实参类型必须对得上，配错是编译错误（不是等 C 编译器来发现）：
`{s}` 要切片、`{c}` / `{b}` 要整数、`{d}` / `{x}` 要整数或浮点。

```zx
std.print("x = {}, y = {}\n", x, y);       // 编译期展开成两次 append
std.println("ptr = {x}", (usize)p);

const f = "value: {}";
std.println(f, 42);                        // f 是 const → 仍走编译期

var fmt: []const u8 = readLine();
std.println(fmt, 42);                      // 运行时解析，行为一致

const alloc = std.heap.page;
var r = std.format(alloc, "{}:{}", i, v);  // → ![]u8
if (r) s {
    std.println("{}", s);
    alloc.free(s.ptr, s.len);
} else e {
    return 1;                              // 分配失败
}
```

编译期路径生成的 C 大致是：

```c
fwrite("x = ", 1, 4, stdout); zx_print_i32(x);
fwrite(", y = ", 1, 6, stdout); zx_print_i32(y);
fputc('\n', stdout);
```

运行时路径生成的 C 是：实参先统一成 `ZxFmtArg`（一个带标签的小结构），交给一次

```c
zx_fmt_out(stdout, fmt, (const ZxFmtArg[]){ zx_fa_i(x), zx_fa_f(y) }, 2, 1);
```

`{any}` 目前按默认格式输出（结构体/联合体的结构化展开还没做）。

### 11.2 结构展开（`{}` 与 `{any}`）

一个值怎么打印，只看它的**形状**，不看它叫什么。聚合值默认 `{}` 就展开——
打印一个地址没有任何信息量。

| 类型 | `{}` | `{any}` |
|---|---|---|
| `i32` / `f64` / `bool` | `-7` / `1.5` / `true` | 同左 |
| `enum` | 整数 `2` | `Color.blue`（带类型名） |
| `struct` | `Point{x: 1, y: 2}` | 同左 |
| 元组 | `{1, "two"}`（无字段名） | 同左 |
| 带标签联合体 | `Shape{circle: 2.5}` | 同左 |
| 普通联合体（无标签） | `Raw{i: 1 \| f: 1.4013e-45}`（成员叠在一起，都打） | 同左 |
| `?T` | `null` / `some(5)` | 同左 |
| `!T` | `ok(7)` / `err(error(3))` | 同左 |
| `[]u8` | 裸字符串 | 带引号和转义：`"a\tb"` |
| 其它 `[]T` | `[10, 20, 30]` | 同左 |
| `*T` | `null` / `0x7ffd…`（只打地址） | 同左 |
| 函数指针 | `fn@0x…` | 同左 |

规则：

- 字段按**声明顺序**，`名字: 值`，逗号分隔；元组没有名字，只有值。
- 嵌套的字符串一律带引号（`P{name: "ab"}`），否则边界看不出来。
- **指针不递归**：链表打出来是 `Node{val: 1, next: some(0x…)}`，不会一路钻下去。
- 深度超过 8 层打 `...`；切片最多打 64 个元素，多的写 `, ...`。
- `{d}` / `{x}` / `{b}` / `{s}` / `{c}` 仍然是"按指定动词打"，不会展开。
- 实现只有一份：编译期路径和运行时路径都调同一个描述符驱动的打印器，
  所以两条路的输出不可能分叉（§11.1 第 3 条）。

## 12. 完整示例

```zx
// 计算一批图形的面积
const std = module("std");

const ShapeTag = enum { circle, rect };

const Shape = union {
    circle: {ShapeTag.circle, f64},
    rect:   {ShapeTag.rect,   {f64, f64}},
};

const Err = enum(u16) { negative = 1 };

const areaOf = fn (s: Shape) !f64 {
    return switch (s.tag) {
        .circle: if (s.circle < 0) (error)Err.negative else 3.14159 * s.circle * s.circle,
        .rect:   if (s.rect.0 < 0) (error)Err.negative else s.rect.0 * s.rect.1,
    };
};

fn main() u8 {
    let shapes = &.{
        Shape{ .circle = 2.0 },
        Shape{ .rect = {3.0, 4.0} },
        Shape{ .circle = -1.0 },
    };

    var total: f64 = 0;
    for (shapes[0..], 0..) s, i {
        if (areaOf(s)) a {
            total = total + a;
        } else e {
            std.println("shape {} bad, code={}", i, (usize)e);
        }
    }

    std.println("total area: {}", total);
    return 0;
}

```

`for (shapes[0..], 0..) s, i` 是本版的多绑定：`0..` 的上界就是 `shapes` 的长度。

## 13. 内存与运行时

- 无 GC、无隐藏分配。堆分配必须显式传分配器：

```zx
const alloc = std.heap.page;
let raw = alloc.alloc(1024);          // ?*u8
if (raw) p {
    let buf = p[0..1024];             // []u8 —— 裸指针加上界才能变切片
    alloc.free(p, 1024);
}
```

- 分配器是**一个结构体值**（`alloc(size) ?*u8` 和 `free(*u8, size)` 两个字段），可以自己造一个（见 `tests/good/arena.zx` 的 bump 分配器）。
- 栈分配是默认；`&.{…}` 落在当前栈帧（`var` 绑定时）；要更多就 `std.stackAlloc` / `std.heapAlloc`（§3.5）。
- 生命周期：字段/元素跟随持有者；`struct` 里的 `var` 是全局单例。
- 没有借用检查、没有生命周期标注、没有 RAII；清理靠 `defer`（§8.6），不靠析构函数。
- 没有 GC，所以指针生命周期只有一条硬规则：**指向当前栈帧的指针不许 return 出去**
  （编译器强制，§3.5）；其余生命周期靠约定，`&.{…}` 的存储跟随所在栈帧。
- `*T` 没有数量，`p[lo..hi]` 必须写上界；分配器回来的 `*u8` 变 `[]T` 就靠这一步。

### 13.1 标准库（`std/`）

编译器随附三个文件，`module("std")` 读的是 `std/std.zx`；它再用 `module("str.zx")` / `module("map.zx")` 挂上字符串工具和哈希表。查找顺序是 `$ZX_STD` → 可执行文件同级的 `std/`、`../std/` → 当前目录。

| 名字 | 形态 | 说明 |
|---|---|---|
| `std.stackAlloc(T, N)` | `*[N]T` | 栈帧上申请一段数组，N 编译期已知（§3.5） |
| `std.heapAlloc(alloc, T, N)` | `*[N]T` | 向分配器要一段数组，OOM 直接 abort（§3.5） |
| `std.heap.page` | `Allocator` | 唯一的现成分配器（malloc/free） |
| `std.print` / `std.println` / `std.format` | 内建 | 见 §11.1 |
| `std.file.read(alloc, path)` | `?[]const u8` | 整个文件读进分配器给的缓冲，末尾补 0 |
| `std.file.write(path, data)` / `append` | `bool` | 覆盖写 / 追加写 |
| `std.file.exists(path)` / `remove(path)` | `bool` | 存在 / 删除 |
| `std.process.args()` | `[][]const u8` | 命令行参数（argv[0] 不在内） |
| `std.process.getEnv(name)` | `?[]const u8` | 环境变量，没有就是 null |
| `std.process.setEnv(name, value)` | `bool` | 写环境变量（只影响本进程及子进程） |
| `std.process.exit(code)` | `noreturn` | 立即退出；它之后的代码编译器拒收 |
| `std.ArrayList(T)` | 泛型类型 | `init/deinit/at/get/set/items/clear/reserve/push/pop/append` + `first/last/insertAt/removeAt/reverse/resize/swap`（v0.13） |
| `std.str.eq/startsWith/endsWith/contains` | `bool` | 比较与探测 |
| `std.str.indexOf/indexOfFrom` | `?usize` | 子串位置 |
| `std.str.trim/trimStart/trimEnd` | `[]const u8` | 去空白，返回原串的视图 |
| `std.str.parseInt` | `?i64` | 十进制，容忍首尾空白与 `+`/`-` |
| `std.str.concat(alloc, a, b)` | `?[]u8` | 拼两段，末尾补 0 |
| `std.str.split(alloc, s, sep)` | `?[][]const u8` | 切开，各段指向原串；`freeSplit(alloc, parts)` 释放 |
| `std.HashMap(V)` | 泛型类型 | 字符串键 → `V`：`init/deinit/put/get/getPtr/contains/count/capacity/keyAt/valueAt/clear` |
| `std.map.fnv1a(s)` | `u64` | 表用的哈希函数，也可以自己拿去用 |
| `std.io.openRead/openWrite/openAppend(path)` | `?usize` | 拿到句柄；失败是 `null` |
| `std.io.read(h, buf)` / `write(h, data)` | `usize` | 读/写**一次**，返回实际字节数（0 = 到头或出错） |
| `std.io.seek(h, off)` | `bool` | 绝对定位 |
| `std.io.tell(h)` / `close(h)` / `flush(h)` | `usize` / `void` | 当前位置 / 关闭（0 句柄是空操作） |
| `std.io.stdin/stdout/stderr()` | `usize` | 三个标准句柄 |
| `std.io.print(h, fmt, args…)` / `println(h, fmt, args…)` | `void` | 往句柄上格式化输出，语法同 §11.1；`println` 结尾补换行 |
| `std.BufReader.open(alloc, path, cap)` | `?BufReader` | 一次读 `cap` 字节，`next()` 按行给（行指向缓冲） |
| `std.BufReader.chunk()` | `?[]const u8` | 不切行，给一块原始字节 |
| `std.BufWriter.create/appendTo(alloc, path, cap)` | `?BufWriter` | 攒满 `cap` 才真写；`write/flush/writeLine/writeByte` |

```zx
const std = module("std");
let al = std.heap.page;

var xs = std.ArrayList(i32).init(al);
if (!xs.push(7)) { return 1; }
std.println("{}", xs.items());
xs.deinit();
```

`ArrayList` 和 `HashMap` 全是普通 Zx 代码（`std/` 下三个文件），没有编译器魔法——所以它们同时也是"怎么写一个泛型容器"的样例。

句柄是 `usize`（里面装的就是 `FILE*`），**0 表示没打开**：`close(0)` / `flush(0)` 是空操作，
所以调用方不用到处判空。句柄不归任何人管——谁开的谁 `close`。

`BufReader` / `BufWriter` 是普通 Zx 代码：缓冲、按行切、翻倍扩容都在库里。
逐行读长文件就四行：

```zx
if (std.BufReader.open(al, "big.txt", 4096)) r0 {
    var r = r0;
    while (r.next()) line { std.println("{s}", line); }   // line 指向内部缓冲
    r.deinit();
}
```

`next()` 给的行**指向内部缓冲**，下一次调用就失效——要留住就自己复制。
行比缓冲还长时缓冲会翻倍，所以"超长行"不会读一半断掉。

`HashMap` 是**字符串键**：开放寻址 + 线性探测，容量是 2 的幂，负载过 3/4 就翻倍。
键不复制（表里存的就是那个切片），所以字符串要比表活得久；没有 `remove`——要删就重建一张表，
这样探测链里没有墓碑，少一个状态少一类 bug。

## 14. 内建（`@` 前缀，不可重定义）

| 内建 | 签名 | 用途 |
|---|---|---|
| `@sizeOf(T)` | `fn(type) usize` | 字节大小 |
| `@alignOf(T)` | `fn(type) usize` | 对齐 |
| `@typeOf(e)` | `fn(any) type` | 取类型 |
| `@typeName(T)` | `fn(type) []const u8` | 类型名 |
| `@typeInfo(T)` | `fn(type) TypeInfo` | 类型描述（编译期值，见 §14.1） |
| `@hasField(T, name)` | `fn(type, str) bool` | 有没有这个字段 / 静态成员 |
| `@fieldType(T, name)` | `fn(type, str) type` | 字段的类型 |
| `@fieldName(T, i)` | `fn(type, usize) []const u8` | 第 i 个字段的名字 |
| `@field(v, name)` | 字段访问 | 按编译期字符串取字段，可读可写 |
| `@ptrCast(T, p)` | | 指针互转 |
| `@bitCast(T, v)` | | 按位重解释 |
| `@intCast(T, v)` | | 检查溢出的窄化 |
| `@trap()` | `fn() noreturn` | 中止 |
| `@compileError(msg)` | `fn([]const u8) noreturn` | 编译期报错 |

`@` 开头保留给内建，用户标识符不能以 `@` 起始。

### 14.1 `@typeInfo(T)`

返回值是**纯编译期值**，六个字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `kind` | `std.TypeKind` | 种类，见下表 |
| `name` | `[]const u8` | 类型名（就是 `@typeName(T)` 那个串） |
| `bytes` | `usize` | 字节数，等于 `@sizeOf(T)` |
| `align` | `usize` | 对齐，等于 `@alignOf(T)` |
| `fieldCount` | `usize` | 结构体/联合体的成员数；枚举的变体数；其余为 0 |
| `fields` | `[]std.FieldInfo` | 字段元表，见下 |

`std.TypeKind` 是个普通枚举，变体名把和关键字撞车的加上下划线：

```
other, void_, bool_, int_, float_, pointer, slice, array,
struct_, union_, enum_, optional, error_union, function, type_
```

`*[N]T` 的 `kind` 是 `.array`（数量在类型里），裸 `*T` 才是 `.pointer`。

```zx
fn kindName(T: type) []const u8 {
    return switch (@typeInfo(T).kind) {
        .int_: "int",
        .struct_: "struct",
        .slice: "slice",
        else: "?",
    };
}
```

因为它整块都是编译期值，`const info = @typeInfo(T);` 之后 `info.kind` / `info.bytes`
都能参与 `switch`、`if` 和数组长度；**没有运行时表示**（真漏到运行时只会得到一块全零）。

配套的查询都是编译期的（`name` / 参数位置接受**编译期字符串**——字符串字面量，
或者 `inline for` 绑定的 `@fieldName(T, i)`）：

- `@hasField(T, "name")` —— 字段或结构体静态成员在不在。
- `@fieldType(T, "name")` —— 字段的类型；不存在就报错。
- `@fieldName(T, i)` —— 第 i 个字段的名字，越界报错。
- `@field(v, "name")` —— 按名字取字段，**可读可写**：`@field(m, "n") = 42;`
  等价于 `m.n = 42;`，名字是编译期常量时行为与 `.name` 完全一致。

**`fields` 元表**把上面这些串成一个整体：`info.fields` 是编译期切片
`[]std.FieldInfo`，元素是 `std.FieldInfo = struct { name: []const u8, ty: type }`
（字段叫 `ty` 而不是 `type`——关键字当不了字段名）。`.len`、下标、`.name`、
`.ty` 全是编译期值，`inline for` 遍历之后 `f.ty` 可以直接当类型用——递归描述、
自动生成序列化 / 比较 / 打印都靠它：

```zx
inline for (0..info.fields.len) i {
    const f = info.fields[i];
    std.println("  {s} : {s}", f.name, @typeName(f.ty));
}
```

TypeInfo / FieldInfo 是**纯编译期类型**（FieldInfo 里装着一个 `type` 值，运行时
没有对应物）：把 `std.TypeInfo` 写成变量类型、把 `std.FieldInfo` 当参数类型都会
被拒绝——引用它们就用 `const info = @typeInfo(T)`，让编译器把值折进常量。

要注意 `.size` 是语言自己的编译期字段（字节数，见 §3），所以描述里用 **`bytes`** 而不是
`size`——叫 `size` 会被 `.size` 规则截胡。

字段遍历用 `inline for`（§8.3.1）。比较任意结构体的泛型函数只需要这几行：

```zx
fn eql(T: type, x: T, y: T) bool {
    const info = @typeInfo(T);
    if (info.kind != std.TypeKind.struct_) {
        return x == y;              // 标量 / bool：直接比
    }
    inline for (0..info.fieldCount) i {
        const FT = @fieldType(T, @fieldName(T, i));
        if (!eql(FT, @field(x, @fieldName(T, i)), @field(y, @fieldName(T, i)))) {
            return false;
        }
    }
    return true;
}
```

| 特性 | Zx | C | Zig |
|---|---|---|---|

## 16. 编译与产物

`zxc file.zx -o prog` 会为**每个模块**生成一份 C 源文件，各自编成 `.o`，最后链接：

```
prog.h            类型定义 + 运行时 + 跨模块原型（所有单元共用）
prog_main.c       入口模块
prog_<stem>.c     每个被引用的模块一份
```

- 类型定义放共享头：同一份 AST 生成的定义必然一致，各单元看到的结构体布局相同。
- 模块导出的函数/全局**不带 `static`**（名字已经带模块前缀，不会撞车），原型/`extern` 声明进头文件。
- 运行时辅助（格式化器、页分配器、`defer` 栈…）是头文件里的 `static` 函数：每个单元一份副本，
  不会重复链接。
- 顶层 `const` 里算不出来的初始化，落在该模块自己的 `zx_init_<stem>()`；入口模块的 `main`
  按依赖顺序依次调用它们。

**增量**：生成的 `.c`（或共享头）内容没变就不重写，`.o` 也就不用重编——改注释、
改空白不会触发重编，改一个模块的实现只有它自己那份 `.o` 会重做。
**时间戳只用来省事，不用来判定正确性**：生成的 `.c` 内容一变，对应的 `.o`
立刻作废（删除），共享头一变则全部作废。秒级 mtime 在同一秒内重写时分辨不出
新旧，曾经表现为"连跑测试随机失败"。

```
$ ZX_VERBOSE=1 zxc main.zx -o prog
  cc prog_main.c
  cc prog_mathx.c
$ ZX_VERBOSE=1 zxc main.zx -o prog        # 什么都没改
$ touch tests/multi/alias/mathx.zx        # 只动 mathx
$ ZX_VERBOSE=1 zxc main.zx -o prog
  cc prog_mathx.c
```

`--emit-c` 仍然是"把全部单元拼成一份打到 stdout"，方便看生成的代码。

### 16.1 回归测试的形态

测试脚本本身也是 Zx 程序（`tools/runner.zx`）：它读源码、按行找断言注释、
拼命令、起进程、比对 stdout。`test.sh` 只是包装，负责编出 runner、
按类别交文件清单，再跑一项"增量编译"检查（那项要看 `ZX_VERBOSE` 输出，
属驱动层行为）。

断言写在用例源码的注释里，工具断言**码与条数**，不断言措辞：

```zx
// expect: division by zero           必须出现在 stderr 里的文字
// expect-code: E0505                 必须出现的错误码（可写多个，空格分隔）
// expect-count: 1                    诊断条数必须正好是多少
// expect-output                      之后每个 `// ` 行是一条期望的 stdout 行
```

**目录约定**：被脚本 glob 直接扫到的文件必须自己就是完整用例；配套模块一律放
子目录（`tests/multi/<name>/main.zx`、`tests/bad/priv/priv-util.zx`）。
"什么算一个用例"由目录结构决定，脚本里不维护例外名单。

## 17. 诊断

### 17.1 格式

```
file.zx:12:9: error[E0403]: cannot assign to 'n': it is not a `var`
```

`文件:行:列: 级别[码]: 消息`。码是稳定的，消息是给人读的——**工具和测试断言码，
不断言措辞**（措辞会为了更准确而改，码不会）。

一次编译会**尽量报完所有错误**，不是遇到第一个就停：

- 语义层每条语句/声明独立检查，错误类型用 `<error>` 吸收，尽量不产生连锁。
- 解析层在声明边界恢复：一个 `fn` 里出了语法错，同步到下一个 `fn`/`const`/
  `struct`… 再继续，后面函数的错照样报。
- 打印上限 30 条（继续计数），结尾汇总 `zxc: N error(s)`；超过上限时说明
  `(first 30 shown)`。级联报错刷屏会把根因埋掉，第一个错通常就是根因。
- **同一位置、同一个码、同一句话只报一次。** 语义检查对同一个表达式可能求值两次
  （定型一次、常量折叠一次），而求值带副作用——去重放在诊断的唯一出口，
  保证用户数到的条数等于摘要里的数字。
- 有语法错时不进语义检查（语法树不完整，语义错基本都是噪声）。

### 17.2 码段

| 段 | 含义 | 例子 |
|---|---|---|
| E01xx | 词法 | E0101 未闭合的字符串/注释；E0102 非法字符或数字后缀 |
| E02xx | 语法 | E0201 `expected X, found Y`；E0202 其他形态错 |
| E03xx | 类型与表达式 | E0301 类型不匹配 / 没有隐式转换；E0302 字面量越界；E0303 参数个数；E0304 没有这个成员；E0305 类型形状（`*i32` 没有数量、`?T` 不能嵌套）；E0306 运算符与操作数（`*` 不能乘指针、序列长度不等）；E0307 聚合字面量（union 必须恰好初始化一个成员） |

## 18. 外部函数（`extern "C"`）

```zx
extern fn puts(s: *const u8) i32;
extern "C" fn strlen(s: *const u8) usize;
```

`extern fn` 声明**名字的意义在编译器外面**：语义层只认签名（参数类型、返回类型、
调用照样做类型检查），后端只发一条 `extern` 原型，不生成函数体。目前只有 C 一种
ABI，写不写 `"C"` 等价；将来出现第二种 ABI 时这个字符串才有意义（写别的直接报错）。

**规则：**

1. 声明处**没有函数体**，也不允许写 `pub`（外部符号本来就是链接级别的）。
2. C 名 = 声明名，**不加模块前缀、不做关键字转义**——`extern fn puts` 就是要
   libc 的 `puts`，加上 `_` 或前缀就链接不到。
3. 标准头（`stdio.h` / `stdlib.h` / `string.h`）里已经声明过的名字**不重复声明**：
   C 里 `char* malloc(uint64_t)` 与 `void* malloc(size_t)` 是冲突类型。用头里的
   声明，调用点按 Zx 这边的签名做转换。
4. `*u8` 在 FFI 边界映射成 `char*`（`*const u8` → `const char*`）：Zx 没有 `char`
   类型，一个字节就是 `u8`；libc 的字符串函数收的都是 `const char*`。指针实参在
   调用点显式转型，避免 `-Wpointer-sign`。
5. `usize` ↔ `size_t`，`i32` ↔ `int32_t`，`*T` ↔ `T*`，`void` ↔ `void`。

**能做什么**：`puts` / `strlen` / `malloc` / `free` 这类定参函数，以及任何你自己
用 `zig cc -c` 编出来的 `.o`（链接时一起给）。**不能做什么**：变参函数
（`printf` 的直接调用——用 `std.print` 替代）、C 宏、C 的结构体按值传递之外的
ABI 特性、回调（`fn` 指针可以传，但 C 那边回调进来的约定还没验证过）。

写长命程序不必再用自定义 arena：`malloc` / `free` 就是现成的。语义上仍然
**没有析构**——谁申请谁释放，和 C 一样。
